# ⚙️ 시스템 오류/글리치 효과(Glitch Effect) 최종 가이드라인 v1.0
*(Video Editor 및 VFX 담당자용)*

이 가이드라인은 콘텐츠의 권위와 위기감을 극대화하는 핵심 시각 언어입니다. 글리치는 단순한 필터가 아니라, **시스템적 결함**을 증명하는 필수적인 '시각적 근거'로 작동해야 합니다. 모든 효과는 사이언 블루/딥 네이비 그리드 패턴과 연동되며, 색상 코드와 타이밍을 엄격히 준수해야 합니다.

---

## 🎨 공통 디자인 원칙 및 규칙
1.  **지속 시간:** 어떤 레벨의 글리치든 최대 노출 시간은 **2~4프레임**을 넘기지 않도록 짧고 충격적으로 처리합니다. 길게 지속되면 '연출'로 느껴져 권위가 하락합니다.
2.  **트랜지션 활용:** 글리치는 컷과 컷이 바뀌는 지점(Transition Point)에 집중적으로 배치하여, 시각적 단절감을 통해 긴장감을 극대화해야 합니다.
3.  **사운드 동기화:** 모든 글리치 효과가 발생할 때마다 **`[SFX: Digital Glitch Burst]`** 사운드를 반드시 삽입하고, 이 소리가 가장 높은 음역대의 피크를 찍도록 편집합니다.

---

## 💾 레벨별 상세 스펙트시 (The Three Levels)

### Level 1: 미세 노이즈/데이터 지터 (Micro Noise / Data Jitter)
**🚨 목적:** 시청자에게 '뭔가 이상하다'는 의구심(Doubt)을 심어주고, 내용의 시작점에서 주의를 환기시키는 역할. (최소한의 위험 경고)

| 항목 | 사양/지침 | 기술적 스펙 | 적용 타이밍 (Writer Script 기준) |
| :--- | :--- | :--- | :--- |
| **발생 원리** | 아주 짧은 순간, 화면 전체에 픽셀 단위의 무작위 오차(Jitter)와 미세한 색상 분리(Chromatic Aberration)가 발생. 마치 영상 신호가 간신히 전달되는 듯한 느낌을 준다. | **색상:** `#0d1b2a` (Deep Navy Base), 노이즈는 `RGB (3, 3, 5)`의 미세 변화만 허용. <br>**빈도:** 4~6프레임마다 무작위로 1~2번 발생. | **[A] 후크 & 문제 제기 초기 단계** (00:00-00:15 사이). 통념을 제시할 때 간헐적으로 사용. |
| **편집 지침** | 배경 영상의 가장 밝은 영역(Highlight)에 노이즈를 집중시켜, '신호 왜곡'처럼 보이게 만듭니다. 절대 패턴적이어서는 안 됩니다. | **애니메이션:** `Random Offset (X, Y)` 픽셀 이동 효과 필수. |

### Level 2: 데이터 스캔라인/시스템 오류 블록 (Data Scanline / System Block)
**🚨 목적:** 콘텐츠가 특정 '결함(Gap)'이나 구조적 문제를 폭로하는 핵심 구간. 시스템이 작동하면서도 내부의 결함을 스스로 노출시키는 과정. (경고 단계)

| 항목 | 사양/지침 | 기술적 스펙 | 적용 타이밍 (Writer Script 기준) |
| :--- | :--- | :--- | :--- |
| **발생 원리** | 화면을 가로지르는 수평 또는 수직의 데이터 블록(Scanline)이 일정 시간 동안 노출됩니다. 이 블록은 일반적인 영상 신호가 아닌, '시스템 로그'나 '오류 코드'처럼 보이게 합니다. (그리드 패턴과 연동 필수) | **색상:** 기본 배경은 `#1b263b` (Navy), 스캔라인은 경고의 의미를 담아 `Cyan Blue (#00ffff)` 계열을 사용하여 강조합니다. <br>**패턴:** 4x4 또는 8x8 그리드 단위로 끊김/겹침 효과 연출. | **[B] 결함 폭로 & 원리 제시** (01:30-02:50 사이). 'A와 C가 만나는 지점', '시스템적 결함' 등 핵심 용어 언급 직후 사용. |
| **편집 지침** | 글리치 효과의 블록 안에는 반드시 **`[ERROR]`** 또는 **`DATA CORRUPTED`** 같은 짧고 기술적인 키워드를 폰트 왜곡과 함께 배치해야 합니다. 이 과정이 곧 '정보 폭로'임을 시각적으로 증명합니다. | **애니메이션:** `Horizontal/Vertical Wipe Effect`가 가장 중요하며, 블록을 지나갈 때마다 사운드 피크를 유지합니다. |

### Level 3: 손실 공포 최대화 경고 (Critical Loss Warning - LMI Trigger)
**🚨 목적:** 최종적이고 측정 가능한 위협(Loss Aversion)을 시각적으로 극대화하는 클라이맥스. **가장 권위적이며, 가장 높은 긴급성을 부여해야 합니다.**

| 항목 | 사양/지침 | 기술적 스펙 | 적용 타이밍 (API Trigger 기준) |
| :--- | :--- | :--- | :--- |
| **발생 원리** | `Loss Crisis Score` API가 0.8 이상을 반환했을 때, 시스템 전체가 다운되는 듯한 시뮬레이션을 보여줍니다. 화면이 왜곡되고, 모든 UI 요소(텍스트, 차트)에 경고 문구가 강제 오버레이 됩니다. | **색상:** 배경은 어두운 `#0a192f` (Near Black Navy). 글리치/경고 폰트는 **강력한 Red (`#ff3d00`)**과 사이언 블루를 동시에 사용하여 충돌감을 극대화합니다. <br>**요소:** 중앙에 거대한 카운트다운 타이머(5초)와 함께, `[LMI ALERT]` 같은 시스템 경고 문구를 폰트를 왜곡시키며 반복 출력해야 합니다. | **Developer API Trigger 지점** (Writer Script의 핵심 전환 구간). 특히 LMI 계산기 시각화가 시작되는 순간부터 강제 작동. |
| **편집 지침** | 이 단계에서는 글리치 효과 자체를 하나의 '시스템 실패' 애니메이션 모듈로 취급합니다. 배경 영상을 잠시 멈추고(Freeze Frame), 그 위에 기술적인 UI 오버레이와 글리치를 중첩하여, 마치 영상이 *실시간으로 시스템 오류*를 일으키는 것처럼 연출해야 합니다. | **애니메이션:** `Jitter + Scanline + Color Shift`의 세 가지 효과를 1초 안에 조합적으로 사용하여 과부하된 느낌을 전달합니다. |
