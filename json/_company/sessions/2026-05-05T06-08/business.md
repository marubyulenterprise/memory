## 📊 개발팀 제출용 Loss Aversion 시나리오 데이터 세트 (API Input Parameter)

개발자님께서 설계하신 `/calculate_loss` API가 작동할 수 있도록, '손실 공포(Loss Aversion)'를 극대화하는 단계별 시나리오 15가지와 정량적 손실액($X$) 산출 기준표를 제공합니다. 이 데이터는 사용자에게 위기감을 주어 제품 구매의 필요성을 강제하는 핵심 입력값으로 사용되어야 합니다.

---

### 💡 $L_1$: 경미한 결함 (Minor Flaw) 시나리오
*   **특징:** 당장 시스템이 멈추지는 않으나, 비효율적인 프로세스 또는 기본 지식의 부재로 인해 *시간적/사소한 금전적 손실*을 초래하는 단계.
*   **목표:** "당신은 기본적인 것도 놓치고 있다"는 권위를 확립하고 관심을 유도합니다.

| No. | 시나리오 (문제점) | 결함의 근거 지식 Gap | 예상 손실액 $X$ 산출 기준 (API Input) |
| :--- | :--- | :--- | :--- |
| **L1-01** | 수동 데이터 취합 및 검증으로 인한 반복 작업 시간 낭비. | API 연동 기반의 자동화 파이프라인 구축 필요성. | **$X = (\text{일별 평균 업무시간} \times 5) / 20 \text{ (만원)}$**<br>(예: 하루 4시간 $\rightarrow$ $10$만원 손실) |
| **L1-02** | 클라우드 비용 최적화 실패로 인한 과도한 리소스 할당. | 서버리스 컴퓨팅 모델(Serverless) 활용 및 트래픽 예측의 중요성. | **$X = \text{월 예상 운영비} \times 15\% \text{ (누수율)}$**<br>(예: $200$만원 $\rightarrow$ $30$만원 손실) |
| **L1-03** | 검색 엔진 최적화(SEO)의 기본적인 메타태그 누락. | 검색엔진 알고리즘 변화에 대응하는 구조적 SEO 설계 원칙 부재. | **$X = \text{월 예상 유입 트래픽} \times 5\% \text{ (노출 기회 상실)}$**<br>(예: $10,000$명 $\rightarrow$ $50$만원 손실) |
| **L1-04** | 기본적인 보안 취약점(XSS 등)에 대한 무지로 인한 단순 정보 유출. | 최소한의 입력값 검증 및 방어 코딩 원칙 미적용. | **$X = \text{잠재 고객 데이터 수} \times 5\text{원/건 (평균 가치)}$**<br>(예: $100,000$명 $\rightarrow$ $50$만원 손실) |
| **L1-05** | 명확한 사용자 여정(User Journey Map) 없이 콘텐츠 기획. | Funnel 단계별 CTA 설계 및 전환율 최적화(CRO) 원칙 부재. | **$X = \text{월 예상 트래픽} \times 2\% \text{ (전환 경로 손실)}$**<br>(예: $50,000$명 $\rightarrow$ $100$만원 손실) |

### 🚨 $L_2$: 중기적 위험 (Mid-Term Risk) 시나리오
*   **특징:** 프로젝트 전반의 방향성이나 기술 스택 선택에 오류가 발생하여 *사업 확장 및 성장 단계에서 심각한 문제*를 초래하는 단계. 전문가의 개입이 필수입니다.
*   **목표:** "지금 당장 전문가의 점검 없이는 다음 레벨로 넘어갈 수 없다"는 위기감을 조성합니다.

| No. | 시나리오 (문제점) | 결함의 근거 지식 Gap | 예상 손실액 $X$ 산출 기준 (API Input) |
| :--- | :--- | :--- | :--- |
| **L2-01** | 비즈니스 로직을 데이터베이스에 직접 코딩(Hardcoding)하여 확장성 저하. | MSA(Microservice Architecture) 설계 원칙 및 관심사 분리(Separation of Concerns). | **$X = \text{추가 기능 개발 예상 기간} \times 3\text{배 (재작업 비용)}$**<br>(예: $2$주 $\rightarrow$ $600$만원 손실) |
| **L2-02** | 법규(GDPR, 국내 개인정보보호법 등) 변화를 예측하지 못하고 데이터 수집. | 글로벌 규제 준수 아키텍처 설계 및 법무 리스크 관리 프로세스 부재. | **$X = \text{예상 매출 규모} \times 0.5\% + \text{벌금 계수}$**<br>(법적 벌금 가중치 적용 필수) |
| **L2-03** | 사용자 피드백을 무시하고 자체 기술 스택에만 의존하는 개발 진행. | 시장 검증(Market Validation) 기반의 MVP 반복 개선 사이클 부재. | **$X = \text{시장 진입 예상 시기} \times 6\text{개월 지연 비용}$**<br>(지체로 인한 기회비용 최대화) |
| **L2-04** | 개발 초기 단계부터 확장 가능한 성능 측정(Load Test)을 무시함. | 트래픽 증가에 따른 병목 구간 예측 및 부하 테스트 시뮬레이션 필요성. | **$X = \text{예상 동시 접속자 수} \times 10\text{원/초 (서비스 중단 시간)}$**<br>(대규모 장애 발생 시) |
| **L2-05** | 전문 지식의 아웃소싱 없이 모든 것을 자체 인력만으로 처리하려 함. | 업무 프로세스 표준화(SOP) 및 외부 전문가 자문 시스템 통합 필요성. | **$X = \text{프로젝트 기간} \times (\text{필요 인원수} - 1) \text{명 $\text{월}$ 비용}$**<br>(결정적 누락된 전문가 영역에 대한 비용 산출) |

### 💣 $L_3$: 회복 불가능한 시스템 오류 (Irreversible System Failure) 시나리오
*   **특징:** 단순 실수 차원이 아닌, 사업의 근간을 흔들거나 *회복하기 극도로 어렵고 막대한 피해*를 주는 단계. 즉각적인 외부 전문가 개입만이 유일한 해결책입니다.
*   **목표:** 공포감을 최고조로 끌어올려 '지금 당장 이 서비스를 사지 않으면 회생 불가능하다'는 느낌을 주도록 설계합니다.

| No. | 시나리오 (문제점) | 결함의 근거 지식 Gap | 예상 손실액 $X$ 산출 기준 (API Input) |
| :--- | :--- | :--- | :--- |
| **L3-01** | 핵심 비즈니스 로직을 중앙화된 단일 장애 지점(SPOF)에 의존. | 분산 시스템 아키텍처 설계 및 백업/복구 계획(DRP)의 부재. | **$X = \text{사업 운영 중단 일수} \times \text{일일 최소 매출액 (Min Daily Revenue)}$**<br>(최대 손실 규모 예측) |
| **L3-02** | 시스템 구축 단계에서 '예외 처리(Exception Handling)'를 고려하지 않음. | 비정상적인 입력값이나 환경 변화에 대응하는 로직의 필수성 간과. | **$X = \text{누적된 잠재 고객 수} \times 1,000\text{원/건 (평생 가치)} + \text{신뢰도 하락 페널티}$**<br>(브랜드 신용 손상 비용 포함) |
| **L3-03** | 데이터 관리 정책 없이 비정형 데이터를 무분별하게 수집 및 보관. | 개인 정보 익명화(Anonymization) 및 보안 거버넌스 프레임워크 미적용. | **$X = \text{최대 예상 법적 벌금} + \text{소송 비용 예측치}$**<br>(규제 당국의 최고 수위의 처벌액으로 설정) |
| **L3-04** | 기술 변화 속도를 읽지 못하고 레거시 시스템에 매몰되어 혁신 실패. | 시장 트렌드를 선도하는 '시스템 전환 로드맵' 및 미래 예측 모델 부재. | **$X = \text{경쟁사 대비 지연된 진입 시기} \times 5\text{배 (시장 점유율 손실)}$**<br>(시장에서 완전히 도태될 경우의 시장 가치 하락) |
| **L3-05** | 시스템 통합(Integration) 단계에서 API 규격 통일성 검토 실패. | 전사적인 기술 표준화 및 인터페이스 정의서(Interface Definition Document, IDD) 작성 의무 무시. | **$X = \text{통합 프로젝트 총 예산} \times 50\% \text{ (재작업률)}$**<br>(전체 재설계가 불가피한 상황을 가정) |
