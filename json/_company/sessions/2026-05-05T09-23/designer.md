### 1. 🎨 전역 시스템 디자인 원칙 (Global System Rules)

| 영역 | 요소 | 스펙/규칙 | 기술적 요구사항 (Developer 참고) |
| :--- | :--- | :--- | :--- |

### 2. ⌨️ 입력 상호작용 상세 스펙 (Input Interaction Specs)

사용자가 `X1` 또는 `X2` 필드에 데이터를 입력할 때 발생하는 미세한 '시스템 오류' 효과를 정의합니다.

| 상황 | 시각적 변화 (Visual Effect) | 애니메이션 로직 (Animation Logic) |
| :--- | :--- | :--- |
| **입력 시작** | 커서(Cursor)가 깜빡이는 것이 아니라, 10ms 간격으로 짧게 '글리치(Glitch)'되며 점멸하는 효과. | CSS `animation: glitch-cursor` 적용. 입력된 문자가 들어오는 순간, 해당 문자에 아주 미세한 수평 분열(`split`)과 노이즈 오프셋을 주어 출력. |
| **데이터 전송 (API 호출)** | 'PROCESSING...' 상태 메시지 표시와 함께, 화면 전체에 짧고 빠른 디지털 노이즈(Static Noise) 효과가 0.2초간 발생해야 함. | `filter: url(#noise)`를 이용한 미세하고 무작위적인 RGB 채널 변형을 적용. 동시에 배경 그리드가 잠시 깨지는 듯한 패턴 변화 (Timecode 기반). |
| **입력 유효성 검사** | 값이 범위를 벗어나거나 누락될 경우, 해당 입력 필드 테두리가 `Warning Red`로 깜빡이며(Blinking), 경고 텍스트가 마치 전송 오류 메시지처럼 화면 하단에 스크롤되어 나타남. | CSS Keyframe 애니메이션을 사용한 강제적인 반복 깜빡임(`keyframes blink`). |

### 3. ⚠️ 위기 상황 및 경고 UI 상세 스펙 (Critical State/Loss Warning)

LCS 점수가 임계점(예: 70점 이상)에 도달했을 때의 최종 시각적 연출입니다. 이 섹션은 **단순한 알림창이 아닌, 시스템의 구조적인 실패를 폭로하는 장치**여야 합니다.

#### A. 배경 및 시간 흐름 제어 (Timecode-Based Background Shift)
*   **트리거:** `LCS Score`가 임계점 이상일 때 작동 시작.
*   **효과:** 주기적으로 배경 그리드 패턴의 색상이 Cyan Blue에서 Reddish-Black(`rgba(255, 71, 87, 0.3)`) 계열로 미세하게 변조됨.
*   **애니메이션:** `Timecode`가 경고 단계에 진입함에 따라 배경 패턴의 밀도가 높아지고, 전반적인 화면 밝기가 급격히 어두워지면서 불안감을 조성해야 합니다 (Depth of Field/Contrast Drop).

#### B. 폰트 애니메이션 및 글리치 효과 (Font & Glitch FX)
*   **Warning Title 등장 시:** 제목이 나타날 때 한 번에 페이드 인(Fade In)되는 것이 아니라, **글자 단위로 불규칙하게(Jittering)** 전송되듯 출력되어야 합니다. 각 문자가 획순을 따라 '띠용'하는 사운드와 함께 순차적으로 활성화됩니다.
*   **System Error/Glitch:** 경고 메시지 출력 시, 해당 컴포넌트 전체에 걸쳐 짧은 시간 동안 (예: 0.1초) **RGB 채널 분리(Chromatic Aberration)** 효과를 주어 '깨진 디스플레이' 같은 느낌을 극대화합니다.
*   **애니메이션 타이밍:** 글리치는 메시지의 가장 강렬한 키워드 또는 수치를 강조할 때마다 반복적으로 발생하도록 스크립트와 연동되어야 합니다.
