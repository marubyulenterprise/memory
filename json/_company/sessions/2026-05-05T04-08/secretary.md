## 🛠️ [기술 명세서] 개인화 손실액(LMI) 계산 및 웹페이지 노출 로직

본 기술 명세서는 '손실 공포(Loss Aversion)'를 핵심 구매 동인으로 삼아, 사용자에게 심리적 위기감을 극대화하고 서비스 도입의 필요성을 정량적으로 증명하기 위한 **개인화 손실액(LMI: Loss of Money/Investment)** 계산 모듈을 정의합니다. 이 명세서는 개발팀이 즉시 구현할 수 있도록 입력 변수, 공식, 출력 UI/UX를 종합하여 작성되었습니다.

---

### 1. 목표 및 원칙 (Goal & Principle)

*   **목표:** 사용자 경험 데이터(Time on Page, 행동 패턴 등)와 업계 평균 데이터를 결합하여 '현재의 비효율성이 초래하는 잠재적 손실액'을 실시간으로 계산하고 시각화한다.
*   **원칙:** LMI는 단순히 금전적인 비용을 넘어 **‘기회비용’과 ‘시스템 오류로 인한 시간 낭비 비용’**을 복합적으로 포함해야 한다. (지식 습득 $\neq$ 돈)

### 2. 입력 변수 정의 (Input Variables Definition)

개발자가 API 엔드포인트나 프론트엔드 이벤트 리스너를 통해 수집해야 하는 데이터 목록입니다.

| 변수명 | 유형 | 설명 | 측정 단위 | 출처 (Source) |
| :--- | :--- | :--- | :--- | :--- |
| `V_SESSION_TIME` | Float | 웹페이지 체류 시간 (세션당 총 시간). | Hour (시간) | Google Analytics/Session Tracker |
| `V_EFFICIENCY_RATE` | Float | 현재 사용자 그룹의 평균 효율성 대비 낮은 비율. (0~1 사이 값) | Ratio (%) | 자체 측정 알고리즘 / DB Query |
| `V_INDUSTRY_COST` | Integer | 해당 산업 분야에서 1년 동안 발생하는 표준적/평균적 최대 손실액. | Currency ($) | Researcher 데이터베이스 |
| `V_GAP_FACTOR` | Float | 사용자의 현재 지식 수준과 목표 달성 사이의 '격차' 정도를 수치화한 계수 (0~1). | Ratio (%) | 자체 진단 퀴즈/폼 입력값 |
| `V_ACTION_PENALTY` | Integer | 비효율적 행동(CTA 무시, 뒤로 가기 등)이 발생할 때마다 가산되는 벌점 금액. | Currency ($) | Front-end Event Listener |

### 3. 계산 공식 정의 (Calculation Formulas)

LMI는 다음 세 가지 주요 구성 요소의 합으로 계산됩니다.
$$ LMI = (\text{시간 손실 비용}) + (\text{비효율성 누적 패널티}) + (\text{잠재적 기회 손실액}) $$

#### 3-1. 시간 손실 비용 (Time Loss Cost, $L_{T}$)
*   사용자가 비효율적으로 보낸 시간에 대한 비용 부과.
$$ L_{T} = V_{\text{SESSION\_TIME}} \times C_{\text{HOUR}} \times (1 - V_{\text{EFFICIENCY\_RATE}}) $$
*   $C_{\text{HOUR}}$: 시간당 기회비용 상수 (예시값 $200).

#### 3-2. 비효율성 누적 패널티 (Inefficiency Penalty, $L_{P}$)
*   사용자가 시스템의 경고 메시지나 핵심 CTA를 무시하거나 이탈할 때마다 가산되는 벌점.
$$ L_{P} = \sum (\text{Event } i) V_{\text{ACTION\_PENALTY}, i} $$

#### 3-3. 잠재적 기회 손실액 (Potential Opportunity Loss, $L_{O}$)
*   가장 핵심적인 부분으로, 현재의 결함(Gap)을 방치했을 때 발생하는 최대 위험 금액을 제시합니다.
$$ L_{O} = V_{\text{INDUSTRY\_COST}} \times V_{\text{GAP\_FACTOR}} \times \text{Multiplier}_{\text{URGENCY}} $$
*   $\text{Multiplier}_{\text{URGENCY}}$: 경고 메시지 노출 빈도에 따라 증가하는 가중치 (예: 최초 진단 시 1.0, 재진단 시 1.2).

#### 최종 LMI 계산식 (Final Formula)
$$ \text{LMI} = L_{T} + L_{P} + L_{O} $$

### 4. 출력값 및 UI/UX 요구사항 (Output & UX Requirements)

개발자는 이 값을 화면에 노출할 때 단순한 숫자가 아닌, **'위기 경보 시스템'**처럼 느껴지도록 구현해야 합니다.

| 요소 | 기술 사양 / 포맷팅 | UX 지침 |
| :--- | :--- | :--- |
| **메인 LMI 수치** | 쉼표(,)를 사용하여 큰 단위의 금액을 명확히 구분 (예: $1,234). | 화면 최상단에 고정 노출. 색상은 **빨간색 경고(Red Alert)** 톤 사용. 숫자가 계산될 때마다 '카운트업(Counting Up)' 애니메이션 적용하여 역동성을 부여해야 함. |
| **손실 근거 요약** | "현재 비효율성으로 인한 잠재적 손실액: $X"와 같은 문장 구조. | LMI 수치 바로 아래에 배치. 어떤 변수들이 이 금액을 구성했는지 간략히 설명 (예: *[시간 낭비] + [시스템 결함 노출]*). |
| **경고 모듈** | 'SYSTEM ALERT' 또는 'CRITICAL FAILURE DETECTED'와 같은 경고 문구 및 글리치 효과(Glitch Effect) 오버레이. | LMI 수치가 특정 임계값($500 이상 등$)을 초과할 때만 활성화되어, 공포감을 극대화해야 함. |
| **데이터 시각화** | 계산된 $L_{O}$ 값을 막대 그래프 형태로 보여주고, 이 막대가 '현재 상태'와 '해결책 도입 후 예상 상태'로 분할되는 구조를 포함한다. | 사용자가 문제의 크기를 직관적으로 이해하고, 해결책이 얼마나 큰 차이를 만들어낼지 시각적 충격으로 전달해야 함. |
