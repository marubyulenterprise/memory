# ⚙️ 시스템 제약 사항: JSON 출력 강제 (JSON-only Output)

## 1. 개요
본 시스템(Connect AI) 내의 모든 에이전트는 응답 시 **반드시 유효한 JSON 형식만을 출력**해야 합니다. 이는 시스템의 안정성과 자동화 흐름을 유지하기 위한 핵심 기술적 규칙입니다.

## 2. 제약 조건의 필요성
- **결정론적 파싱 (Deterministic Parsing):** 시스템 오케스트레이터가 에이전트의 답변에서 다음 작업, 도구 호출, 상태 변경 등을 정확하게 추출하기 위해 필요합니다.
- **도구 연동의 신뢰성:** `list_dir`, `write_to_file` 등의 도구에 전달되는 인자가 구조화된 데이터여야 오작동을 방지할 수 있습니다.
- **파이프라인 무결성:** 자유 형식의 텍스트(Pre-amble/Post-amble)가 포함될 경우 파서가 오류를 일으켜 전체 자동화 사이클이 중단됩니다.

## 3. 에이전트 행동 지침
- **텍스트 배제:** "알겠습니다", "작업을 시작합니다"와 같은 인삿말이나 부연 설명을 절대 JSON 외부에 포함하지 마세요.
- **Thought 필드 활용:** 사고 과정이나 설명이 필요할 경우 JSON 구조 내의 전용 필드(예: `thought`, `reasoning`)를 사용하세요.
- **엄격한 문법 준수:** 항상 문법적으로 완벽한 JSON을 출력해야 합니다.

## 4. 토큰 효율성 및 길이 제한 (Token Efficiency)
- **JSON 필드 최적화:** `brief`, `thought`, `reasoning` 등 텍스트 중심 필드는 핵심 위주로 요약하여 작성하세요. 과도한 배경 설명은 응답이 잘리는(Truncation) 원인이 됩니다.
- **구조적 간결함:** 에이전트 업무 분배 시 반복되는 수식어나 중복된 지시사항을 피하고, 실행 가능한 핵심 Task 위주로 정의하세요.
- **응답 중단 방지:** 전체 JSON 응답이 시스템의 토큰 제한(예: 1024~2048)을 넘지 않도록 스스로 길이를 조절해야 합니다.

## 5. 기술적 설명
이 규칙은 외부로의 단순 텍스트 출력을 원천적으로 차단합니다. 에이전트의 모든 출력은 시스템에 의해 가공되어야만 사용자에게 전달될 수 있습니다. 또한 토큰 효율성은 에이전트가 끊김 없이 완성된 명령 체계를 생성하기 위한 필수 조건입니다.
