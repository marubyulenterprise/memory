## 🚨 [핵심 산출물] 위기 전환용 UI/UX 컴포넌트 스펙 (Red Alert V4.0 + Paywall Gate)

### 1. Warning Overlay Component (`<WarningOverlay />`)
이 컴포넌트는 `LossIndexSimulator`가 특정 임계치(예: Loss Index > 85% 또는 Time Remaining < 3초)에 도달했을 때, 기존 UI 위에 강제로 오버레이되어 모든 콘텐츠를 차단하는 역할을 합니다.

| 항목 | 스펙 상세 (Technical Spec) | 디자인 목적 및 UX 가이드라인 |
| :--- | :--- | :--- |
| **트리거 조건** | `LossIndexSimulator` State가 Critical(Red Alert)로 전환될 때, 또는 타이머(`Timer`)가 0에 근접할 때. | 사용자가 가장 집중하고 몰입한 순간에 강제로 개입하여 공포를 극대화합니다. |
| **시각적 효과** | **깜빡이는 애니메이션 (Flicker):** 빨간색과 블랙 간의 고속 깜빡임(0.1초 주기)을 적용하여 불안감을 유발. <br>**글리치 오버레이:** 전체 화면에 3D 글리치 필터를 덮고, 좌우로 수평 스크롤되는 노이즈를 추가합니다. (투명도 70% 이하 유지). | 전문적인 시스템 오류나 치명적 결함처럼 보이게 하여 신뢰성 있는 '위기'임을 각인시킵니다. |
| **핵심 문구** | **`🚨 CRITICAL ALERT: [데이터 주권] 손실 임계치 초과!`**<br>*(서브 텍스트)*: 현재 시스템은 외부 규제 리스크에 노출되어 있으며, 실시간 방어막이 무너지고 있습니다. 즉각적인 점검이 필요합니다. | 막연한 불안 대신 구체적이고 전문적인 '위협'을 제시하여 문제의 심각성을 높입니다. |
| **배경 처리** | 모든 하부 콘텐츠를 어둡게 블러(Blur) 처리하고, 중앙에 팝업창만 선명하게 남겨 사용자의 시선이 오버레이 위로 고정되도록 유도합니다. | 다른 정보가 눈에 들어오지 않게 만들어 '지금 이 경고' 외에는 아무것도 중요하지 않은 상태를 만듭니다. |

### 2. Paywall Gate Component (`<PaywallGate />`)
Warning Overlay가 해제되고, 사용자가 해결책을 찾으려 스크롤링을 시도할 때 나타나는 결제 장벽입니다.

| 항목 | 스펙 상세 (Technical Spec) | 디자인 목적 및 UX 가이드라인 |
| :--- | :--- | :--- |
| **시각적 구조** | 메인 컨텐츠 영역에 붉은색/어두운 회색의 경계선과 함께 `[ACCESS RESTRICTED]` 배너가 걸립니다. (높이 약 300px). <br>배경에는 미세한 '시스템 비활성화' 패턴(Dark Grid)을 적용합니다. | 콘텐츠에 대한 접근 권한이 **외부 요인** 때문에 차단되었음을 암시하여, 스스로의 부족함이 아닌 시스템 문제로 포지셔닝합니다. |
| **핵심 메시징** | **헤드라인:** "현재 상태로는 리스크를 막을 수 없습니다."<br>**설명:** "최신 규제 환경에 맞춘 실시간 모니터링 및 방어 로직(System Check Module)이 필수입니다. 이 진단 결과는 핵심 시스템 점검 없이 무의미합니다." | 해결책 자체가 돈으로 팔리는 '필수적인 안전 장치'라는 인식을 심습니다. 지식 판매가 아님을 강조합니다. |
| **CTA 설계** | 1. **주요 CTA (Primary):** `✅ [System Check Module] 즉시 점검 받기 ($XX만원)` <br>2. **보조 CTA (Secondary, 위축형):** `❌ 나중에 확인하기` (비활성화/회색 처리) | '즉시'라는 시간 압박과 함께 구체적인 금액을 제시하여 행동 결정을 강제합니다. 보조 CTA는 물리적으로 누르기 어렵게 만듭니다. |
| **상세화 요소** | Paywall Gate 하단에 "점검하지 않았을 때 예상되는 손실액 예측 그래프" (미리 산출된 가상의 데이터)를 작게 배치하여, 결제 결정의 근거를 시각적으로 제공합니다. | 'Buy-in'이 아닌 'Loss Avoidance' 기반으로 구매 결정을 유도하는 증거를 제시합니다. |

## 🔗 [활용 예시] 통합 Funnel 모킹 (Mockup Usage Flow)

**[페이지 흐름: Free Diagnosis $\rightarrow$ Red Alert $\rightarrow$ Paywall Gate]**

1. **(Start)** 사용자가 무료 진단 페이지(`LossIndexSimulator` 작동 중)를 탐색합니다. (톤: 전문적, 사이언 블루).
2. **(Mid-Process)** `Loss Index`가 점차 증가하며 그래프에 빨간불이 들어오기 시작합니다. (Warning Bar 활성화).
3. **(Trigger Point - 15초 지점)** 개발자가 구현한 `LossIndexSimulator`가 임계치($L_{crit}$)를 돌파합니다.
    *   **[Action]** 기존 UI 전체에 `<WarningOverlay />`가 즉시 오버레이됩니다. (빨간색 깜빡임, 글리치 효과 발생).
    *   **[Visual Output]** 모든 스크롤과 정보는 막히고, 빨간 경고 메시지만 화면을 압도합니다.
4. **(Conversion Blockade)** 사용자가 '이걸 해결할 방법'을 찾기 위해 페이지를 탐색하려 할 때, 배경에 `<PaywallGate />`가 나타나며 모든 콘텐츠 접근을 물리적으로 차단합니다.
    *   **[Visual Output]** 중앙에 경고 오버레이가 남아있는 상태에서, 하단에 Paywall Gate가 위치하며 **'이 해결책은 유료 모듈로만 제공됩니다.'**라는 메시지를 강력하게 전달합니다.
