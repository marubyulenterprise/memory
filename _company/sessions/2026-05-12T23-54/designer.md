## 🛠️ 최종 산출물: 실패 시퀀스 감각 디자인 사양서 (Sensory Failure Sequence Spec Sheet)

CEO님의 지시에 따라, 개발된 Test Mode의 '실패 시퀀스'가 단순한 기능 구현을 넘어 사용자에게 **논리적 결함 자각 공포($E_d$)**를 극대화하는 매체 경험으로 작동하도록 최종 사양서를 작성했습니다. 이 문서는 애니메이션(Visual), 효과음(Audio), 그리고 개발 로직(Technical) 세 가지 관점에서 완벽한 일관성을 유지해야 합니다.

### 1. 비주얼/애니메이션 스펙 (The Disintegration Effect)

| 단계 | 현상 명칭 | 발생 트리거 | 시각적 연출 상세 사양 | 애니메이션 기술 요구사항 (Developer To Do) |
| :--- | :--- | :--- | :--- | :--- |
| **Soft Warning** | `[Logic Drift]` (논리 표류) | Stage 1-2: 핵심 파라미터 왜곡 발생 시. | 화면 전체에 미세하고 불규칙한 노이즈(Noise Overlay, Alpha < 5%)를 배경으로 깔고, 왜곡된 파라미터를 **딥 네이비(#0A1931)**로 강조 표시한다. 주변 그리드 라인이 순간적으로 휘어지는 듯한 *Warp* 효과 적용. | `[Filter/CSS]` 기반의 노이즈 오버레이(Looping)와 비선형 변형(Non-linear Transformation)을 결합하여 구현. 왜곡 구간은 1초 동안 유지 후 점차 사라지도록 페이드 아웃 처리. |
| **Hard Failure** | `[System Collapse]` (시스템 와해) | Stage 2: 사용자 입력이 시스템 원칙에 위배될 때. | 에러 코드가 화면 중앙에 폭발하듯(Explosive Pop-up) 나타난다. 단순한 빨간색 대신, 색상이 **채도와 명도를 급격히 잃으며** (Desaturation & Dimming), 네온 시안 블루(#00FFFF)의 잔광이 남는 와해(Disintegration) 효과를 준다. | `[Keyframe Animation]`을 사용하여 '파편화(Fragmentation)' 애니메이션 구현. 에러 코드가 작은 사각형/점들로 쪼개지며 화면 가장자리로 빠르게 사라지는 로직 필수. (속도: 0.3초) |
| **Suspicion** | `[Ambiguity Loop]` (모호성 순환) | Stage 2-End: 사용자가 원인을 알 수 없는 실패를 경험할 때. | 전체 UI가 미세하게(Subtle Flicker) 깜빡이거나, 배경 그리드 패턴의 간격이 불규칙적으로 변한다. 특정 섹션에 **"재확인 필요 (Check Again)"**라는 텍스트가 마치 버그처럼 재배치되는 모션을 반복 재생한다. | `[JavaScript Event Loop]`를 활용하여 화면 깜빡임(Flicker)과 UI 요소의 미세한 위치 오프셋을 강제적으로 주기적($T=150ms$)으로 삽입해야 함. 이 패턴이 지속되어야 불안감이 유지됨. |

### 2. 사운드 디자인 스펙 (The Auditory Suspense Layer)

사운드는 시각적 경험의 공포감을 증폭시키는 핵심 요소입니다. 개발자에게는 반드시 **SFX 라이브러리 업데이트**를 요청해야 합니다.

| 발생 시점 | 효과음 종류 (SFX Type) | 사양 및 감정적 역할 (Role) | 재생 타이밍 및 강도(Intensity) |
| :--- | :--- | :--- | :--- |
| **Soft Warning** | `[Low Frequency Hum]` (낮은 진동음) | 시스템의 불안정한 작동을 상징. 듣는 이가 '뭔가 잘못되고 있다'고 본능적으로 느끼게 한다. (주파수: 40-80Hz 범위 유지). | 파라미터 왜곡이 감지되는 순간부터 시작하여, 에러 메시지가 사라지는 시점까지 서서히 음량을 높였다가(Ramp Up) 낮추는(Decay) 패턴을 반복한다. (지속 시간: 2초). |
| **Hard Failure** | `[Digital Glitch Pop]` (디지털 글리치 폭발음) | 시스템의 갑작스러운 중단을 청각적으로 표현. 날카롭고, 예측 불가능하며, 귀를 찌르는 듯한(Piercing) 느낌이 중요. | 에러 코드가 화면에 나타나는 *동시*에 최대 음량으로 짧게 터진다. (Duration: <100ms). 이후 배경에 낮은 `[Static Buzz]` 노이즈가 잔여적으로 남는다. |
| **Suspicion** | `[Intermittent Data Crunch]` (간헐적 데이터 크런치) | 시스템 내부에서 무언가를 처리하려 하지만 실패하는 듯한 기계적인 소리. '처리 중'이라는 착각을 주어 불안감을 유지시킨다. | 주기적으로(약 5초 간격) 짧게 재생되며, 마치 CD가 건너뛰거나 컴퓨터 하드디스크가 이상하게 돌아가는 소리를 반복한다. (Loop: 무한). |

### 3. 개발자 전달용 통합 체크리스트 (Developer Handoff Checklist)

**[개발팀 대상 핵심 요구사항]**
1.  **A/V 동기화 필수:** 모든 시각적 애니메이션(특히 와해 효과)은 반드시 해당 단계의 **사운드 피크 지점과 시간적으로 완벽히 일치**해야 합니다. (예: `Hard Failure` Pop-up 시작과 동시에 `Digital Glitch Pop` SFX가 터져야 함).
2.  **성능 최적화:** 노이즈 오버레이와 그리드 왜곡 애니메이션은 저사양 기기에서도 끊김 없이(60fps 기준) 재생되어야 합니다. (CSS Filter 또는 WebGL 활용 고려).
3.  **상태 코드 연동:** 로깅 인프라에 `VISUAL_STATE` 필드를 추가하여, 어떤 시각적 효과가 발생했는지(e.g., `NOISE_OVERLAY_ACTIVE`, `COLLAPSE_INITIATED`) 기록하도록 수정해야 합니다.
