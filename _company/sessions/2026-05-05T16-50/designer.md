# 🛠️ 최종 랜딩 페이지 UX/UI 및 인터랙티브 스펙 시트: ASV Critical State Funnel

CEO의 지시와 이전 로그를 종합하여, 마케팅 퍼널의 핵심 전환점인 'ASV 점수 측정' 섹션을 중심으로 한 **기술적 사양서(Technical Specification Sheet)**를 완성합니다. 단순 와이어프레임이 아닌, 개발팀과 모션 디자이너가 즉시 구현할 수 있도록 애니메이션 로직과 시스템 오류 시각화에 초점을 맞췄습니다.

---

## 🎯 1. 디자인 목표 및 핵심 논리 (Design Goal & Logic)

| 영역 | 설명 | 사양 반영 포인트 |
| :--- | :--- | :--- |
| **목표** | 사용자에게 'ASV 점수'를 통해 현재 시스템의 결함(Gap)을 측정하게 하여, 스스로 문제에 대한 공포와 해결책 의존성을 느끼게 한다. | 모든 시각적 요소는 **'시스템 오류/경고'** 톤앤매너를 유지해야 함. |
| **전환 구조** | 평온한 진입 $\to$ 데이터 입력(데이터 수집) $\to$ 처리 과정(긴장감 조성) $\to$ Critical State 폭로 (공포 극대화) $\to$ CTA 강제 유도 | 애니메이션의 타이밍과 효과가 스토리텔링을 이끌어야 함. |
| **핵심 감정** | 공포(Fear) $\to$ 불안(Anxiety) $\to$ 필요성(Necessity) | 색상, 노이즈, 폰트 변화로 감정을 유도한다. |

## 🖼️ 2. 와이어프레임 및 플로우 정의 (Mockup & Flow Definition)

**[페이지 구조]**
*   **A.** 헤더/인트로: ASV Score가 무엇인지 간결하게 정의하며 신뢰도를 구축 (Deep Navy, Cyan Blue 사용).
*   **B.** 입력 섹션: 사용자 데이터 입력 유도. 가장 깨끗하고 전문적인 UI를 유지하여 '정상 상태'의 느낌을 부여한다.
*   **C.** **[Critical State Zone] ASV 계산 및 폭로:** 이 섹션 전체가 핵심이다. 사용자가 데이터를 넣고 버튼을 누른 후, 화면이 시스템적으로 파괴되는 경험을 제공해야 한다.
*   **D.** 해결책 제시/CTA: 공포를 느낀 사용자에게 유일한 출구(Blueprint)를 제시한다.

### 🖥️ 세부 와이어프레임 스펙 (Critical State Zone - C)

| 요소 | 내용 및 기능 | 애니메이션 사양 (Technical Spec) |
| :--- | :--- | :--- |
| **[ASV 입력 필드]** | 사용자 데이터(예: 현재 시스템 사용 비율, 예외 처리 경험 등)를 수동으로 입력받는 모듈. | 정상 상태에서는 미니멀한 사이언 블루 라인만 표시된다. |
| **[진입 버튼]** | "ASV 점수 진단하기" (Click Point). | 클릭 시 즉시 애니메이션 시작. 버튼의 텍스트가 빠르게 'Processing...'으로 변하며 로딩 바(Cyan Blue)가 움직인다. |
| **[로딩/처리 화면]** | 시스템이 데이터를 분석하는 것처럼 보이지만, 실제로는 공포를 조성하는 과정이다. | 배경에 미세한 **데이터 노이즈 필터링 효과** (Noise Filter Overlay: 5% 투명도). 주기적으로 `PROCESSING...` 경고 메시지가 깜빡이며 나타났다 사라진다. |
| **[ASV 점수 폭로]** | 최종 ASV Score와 결함의 원인(Architectural Debt)이 출력되는 순간. | **★최대 임팩트 구간★**: 화면 전체가 0.1초간 블랙 아웃되었다가, 글리치 노이즈 필터링과 함께 재개된다. 점수 주변으로 `ERROR`, `WARNING` 경고 문구가 빨갛게(Critical Red) 깜빡인다. |
| **[CTA 유도]** | "당신의 시스템은 위험합니다. 전문가의 진단이 필요합니다." 메시지 노출. | 공포가 최고조에 달한 직후, 화면 전체를 덮는 커다란 Critical Red 경고 배너와 함께 `Blueprint Solution` 버튼을 배치한다. 이 버튼만 Cyan Blue로 대비되어 보인다. |

## ✨ 3. 인터랙티브 애니메이션 스펙 시트 (The Technical Specs)

### A. 글리치(Glitch) 효과 로직
*   **적용 타이밍:** ASV 점수 폭로 순간, 그리고 Critical State 경고 문구 노출 직후.
*   **기술 사양:**
    *   **효과 유형:** VHS/CRT 스캔라인 + 데이터 패킷 오류 시뮬레이션.
    *   **주기(Frequency):** 150ms ~ 300ms 간격으로 반복적 깜빡임 발생 (Randomized).
    *   **색상 오프셋:** RGB 채널을 강제로 분리하여 $(R+20\%, G-10\%, B+10\%)$의 색상 변조를 짧게(50ms) 적용한다.
    *   **시각적 목표:** 시스템이 순간적으로 붕괴했다가 다시 복구되는 듯한 착시 효과.

### B. 노이즈 필터링 및 데이터 흐름 (Noise & Data Flow)
*   **적용 타이밍:** '로딩/처리 화면' 전체, 그리고 Critical State Zone의 배경.
*   **기술 사양:**
    *   **필터:** 고해상도 검은색/회색 노이즈 오버레이 (Overlay: 3-5% 투명도).
    *   **움직임:** 미세한 랜덤 움직임을 주어(Perlin Noise) 정지된 화면처럼 보이지 않게 한다. 마치 녹화 장비에 문제가 생긴 듯한 느낌을 준다.
    *   **배경 요소:** 데이터 패킷이 좌측 상단에서 우측 하단으로 흐르는 애니메이션 라인 (Cyan Blue, 반투명). 이 라인이 때때로 끊기거나 튕겨 나가는(Glitch) 연출을 추가한다.

### C. 색상 및 타이포그래피 변화 가이드
| 단계 | 메인 컬러 | 강조 컬러 | 폰트톤/스타일 | 감정적 목표 |
| :--- | :--- | :--- | :--- | :--- |
| **초기 진입** | Deep Navy (#0B1628) | Cyan Blue (#00C4CC) | Sans-serif (고딕체), 간결하고 명확한 계층 구조. | 신뢰, 전문성, 접근 가능성 |
| **문제 제기/경고** | Dark Gray / 블랙 | Critical Red (#D93025) | Monospace Font (터미널 콘솔 느낌). 경고 문구는 대문자(ALL CAPS) 필수. | 위협, 위험, 긴급함 |
| **Critical State** | 블랙 배경 + 노이즈 필터 | Critical Red & Cyan Blue 혼합 | 깨짐 효과가 가해진 폰트 (Distorted Font) 사용을 고려. | 공포, 구조적 결함 폭로 |
