### ⚙️ ASV진단 프로토타입: 인터랙션 디자인 시스템 (V3.0)

**목표:** 사용자 여정의 각 단계에서 '고급 보안 장치'와 같은 전문성과 권위를 부여하고, 데이터 처리 과정을 하나의 트랩(Trap)으로 만듭니다.
**핵심 원칙:** 모든 상호작용은 **미세한 오류/경고 시각 효과**를 포함해야 합니다.

#### 1. Input State (입력 필드 인터랙션)

| 요소 | 액션 (Interaction) | 비주얼 변화 스펙 (CSS/Visual Spec) | 의도 및 UX 목표 |
| :--- | :--- | :--- | :--- |
| **ASV 점수 입력 필드** | `:focus` (클릭 시점) | 1. **Border:** `2px solid #00BCD4` (Cyan Blue). 2. **Box-shadow:** `0 0 8px rgba(0, 188, 212, 0.5)` (Soft Glow 효과). 3. **Label/Placeholder:** 글자색이 `#00BCD4`로 미세하게 변하며 'Active' 상태임을 표시. | 사용자의 입력 행위를 시스템적으로 인식하고 포커싱하는 느낌 부여. 단순한 웹사이트 필드 이상의 기술적 느낌 강조. |
| **입력 값 (숫자)** | 입력 중 (`:active`) | 1. **Input Text:** 타이핑되는 글자가 일반적인 검은색이 아닌, 미세하게 어두운 `#333` 계열로 표시됨. 2. **Curser/Caret:** 기본 커서보다 약간 두껍고 깜빡임 속도가 느리게 (CSS `animation-duration: 0.9s`) 설정되어 '데이터 처리 중' 같은 느낌 부여. | 입력 행위를 시스템의 데이터 스트림으로 인식하게 만듦. |
| **개인 정보 필드** | `:hover` (마우스 오버) | 배경색이 미세하게 (`#F5F7FA`) 어두워지며, 하단에 1px Cyan Blue 라인이 부착됨. | 사용자가 특정 데이터 영역을 '선별'하고 있다는 느낌 부여 (Scanning effect). |

#### 2. Submission State (제출 버튼 인터랙션)

| 요소 | 액션 (Interaction) | 비주얼 변화 스펙 (CSS/Visual Spec) | 의도 및 UX 목표 |
| :--- | :--- | :--- | :--- |
| **진단 시작 버튼** (`Diagnosis Button`) | `:hover` (마우스 오버) | 1. **Background:** `#0288D1` (Deep Blue) $\to$ `#00BCD4` (Cyan Blue)로 부드럽게 그라데이션 변화(Transition: `background-color 0.3s ease`). 2. **Border:** 경계선이 미세하게 깜빡이는 효과 (`box-shadow: 0 0 5px rgba(0, 188, 212, 0.8); animation: pulse 1.5s infinite;`) | 단순 클릭 유도 버튼이 아닌, '시스템 작동 전 최종 점검'을 거치는 기계 장치 같은 느낌 부여. |
| **진단 시작 버튼** | `:active` (클릭 시점) | 배경색이 순간적으로 어두운 `#014C7D`로 변하며, 전체 컴포넌트가 미세하게 수축했다 확장하는 애니메이션 (`transform: scale(0.98);`)을 적용. | 물리적인 버튼 클릭의 느낌을 강화하여 몰입도를 높이고, 시스템 작동 시작에 대한 기대감을 최고조로 끌어올림. |

#### 3. Processing State (시스템 부하 및 트랩 구간)

이 단계는 가장 중요한 '공포 경험'입니다. 시각적 불안정성을 극대화해야 합니다.

| 요소 | 액션 (Interaction) | 비주얼 변화 스펙 (CSS/Visual Spec) | 의도 및 UX 목표 |
| :--- | :--- | :--- | :--- |
| **전체 화면** | `Processing` 상태 진입 시 | 1. **Background Overlay:** 전체 화면에 낮은 투명도의 노이즈 패턴 오버레이 (`background-image: repeating-linear-gradient(0deg, rgba(25, 25, 25, 0.1), transparent 1px);`). 2. **글리치 애니메이션:** 주기적으로 (0.2초 간격) 화면의 좌/우가 픽셀 단위로 미세하게 흔들리고 색상이 번지는 효과(`filter: hue-rotate(-5deg) contrast(1.1); animation: glitch 4s infinite linear;`). | 시스템이 정상적으로 작동하지 않는 '불안정한 상태'임을 시각적, 청각적으로 인지시킵니다. (ASV 경험의 핵심). |
| **로딩 메시지** | 데이터 처리 중 | 로딩 바가 일반적인 선형 진행 방식이 아닌, 마치 **데이터 패킷을 재구성하는 과정**처럼 좌우에서 끊어지고 연결되는 모듈식 애니메이션으로 구현. 텍스트는 `Processing Data Stream...`과 같이 시스템 로그 형식을 사용. | 단순한 대기 시간이 아니라, 복잡하고 중요한 '데이터 처리'가 일어나고 있다는 권위적인 느낌 부여. |

#### 4. Critical State Display (결함 폭로 시퀀스)

| 요소 | 액션 (Interaction) | 비주얼 변화 스펙 (CSS/Visual Spec) | 의도 및 UX 목표 |
| :--- | :--- | :--- | :--- |
| **ASV 결과 영역** | 'Critical State' 진입 순간 | 1. **화면 전환:** 모든 라이트닝 효과가 강한 깜빡임(Flickering, `animation: blink 0.1s infinite`)과 함께 빨간색 경고색 (`#FF3D00`)으로 급격히 변함. 2. **전체 UI:** 표준 사이언 블루/딥 네이비 패턴이 깨지고, 화면 가장자리가 노이즈와 사각형의 `Artifact`처럼 왜곡됨. | '시스템적 결함'이라는 공포감을 시각적으로 극대화하여 사용자에게 충격을 주고 다음 단계(솔루션 제시)로 강제 유도. |
| **핵심 메시지** | 결과 텍스트 출력 시 | 폰트 크기와 두께가 급격히 커지고, 글자가 마치 컴퓨터 터미널의 `Typewriter` 효과처럼 한 글자씩 타이핑되는 애니메이션을 적용함. (예: `CRITICAL VULNERABILITY DETECTED`) | 메시지에 엄청난 중요도와 권위를 부여하여, 이 정보가 단순한 통계가 아닌 '경고'임을 각인시킴. |
