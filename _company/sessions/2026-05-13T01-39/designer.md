# ⚙️ [MARUBYUL] 인터랙티브 오류 시퀀스 디자인 시스템 (V1.0)

**목표:** 사용자가 '시스템적 결함'에 직면했을 때, 전문적이면서도 불안감을 유발하는 경험(Performance)을 제공하고, 이를 통해 진단 장치 접근의 필요성($E_d$)을 강제한다.

## 1. 🎨 디스인티그레이션 (Disintegration) 효과 가이드라인

이 효과는 시스템 오류가 감지되는 **B 단계 (의혹 발생)**에 핵심적으로 사용됩니다. 단순한 화면 깜빡임이 아닌, 데이터와 구조물이 해체되는 과정을 보여줘야 합니다.

### A. 상태 정의 및 트리거
| 상태 | 이름 | 시각적 목표 | 트리거 조건 | 지속 시간 (권장) |
| :--- | :--- | :--- | :--- | :--- |
| **State 1** | **미세 노이즈 감지** | 배경에 미약한 CRT 스타일의 주파수 간섭(Interference) 발생. | 사용자가 핵심 데이터 입력 직후, 또는 특정 시간 활동 없음 (3초). | 0.5초 |
| **State 2** | **논리적 단절 경고** | 화면 주요 요소(다이어그램, 박스 등)의 모서리가 떨리고, 색상이 불안정하게 왜곡됨. | 시스템이 입력된 데이터와 내부 로직 간의 '모순'을 감지했을 때. | 1.0초 |
| **State 3** | **시스템 와해 (Disintegration)** | 화면 전체가 글리치(Glitch) 및 아날로그 노이즈로 뒤덮이며, 핵심 메시지가 강제 오버레이됨. | $E_d$ 스코어가 임계치를 초과했을 때. **(핵심 전환점)** | 2.0초 |

### B. 시각적/색상 스펙 (Hex Code 필수)
| 요소 | State 1 (노이즈 감지) | State 2 (논리적 단절) | State 3 (시스템 와해) |
| :--- | :--- | :--- | :--- |
| **배경 색상** | `#0A192F` (Deep Navy Base) | `#184B7E` (Cyan Shifted Blue) | `#000000` (Black Void) + 노이즈 오버레이 |
| **글리치/오류색 1** | `rgba(255, 165, 0, 0.1)` (Weak Amber Flicker) | `rgba(255, 0, 255, 0.2)` (Magenta Glitch Trail) | `rgba(255, 255, 0, 0.4)` (Yellow Static Block) |
| **글리치/오류색 2** | - | `rgba(173, 216, 230, 0.3)` (Pale Aqua Shift) | `rgba(255, 69, 0, 0.6)` (Orange Corruption Flash) |
| **애니메이션 효과** | 주파수 변화 노이즈 필터링 적용. | *Shift:* 요소의 X/Y축 위치가 비동기적으로 떨리며(Jitter), 색상 값이 순간적으로 플립됨. | *Glitch:* 2~3프레임 단위로 화면의 가로/세로 일부 블록이 강제 이동 및 왜곡되며, 노이즈 필터링을 최대화함. |

## 2. ✒️ 타이포그래피 변화 (Typography Shift) 가이드라인

텍스트가 단순히 빨갛게 변하는 것이 아니라, '디지털 데이터의 오류'처럼 보여야 합니다.

### A. 기본 설정 및 실패 로직
*   **기본 폰트:** Pretendard (Systematic/Technical 느낌 유지)
*   **실패 시 사용 폰트:** Monospace Font (예: Inconsolata 또는 Courier New). 코드가 깨진 듯한 인상을 주기 위함.

### B. 오류 발생 시 텍스트 변형 로직
1.  **Character Shift (Stuttering):** 문자가 한 글자씩 떨리거나(Jitter), 일정한 간격으로 깜빡이는 애니메이션을 적용한다. (속도: 50ms 간격).
2.  **Data Corruption (Bit-Flipping):** 특정 문자열이나 단어에 대해, 임의의 비트가 뒤집힌 듯한 효과를 주거나(예: `[A] -> [a/A]`), 아스키 코드가 깨진 것처럼 보이는 텍스트로 대체된다.
3.  **Over-Emphasis:** 오류 메시지가 나올 때, 핵심 단어는 일반 폰트 대신 **굵은 고정폭 글씨체 (Bold Monospace)**로 강제 출력되어 전문적인 '코드'처럼 보이게 한다.

## 3. 🔊 노이즈 기반 오류 메시지 및 사운드 디자인

오류가 발생했을 때, 사용자에게 "무언가 잘못되었다"는 감각적 충격을 주어야 합니다.

### A. UI 컴포넌트: [System Alert Box]
*   **배치:** 화면 중앙 하단에 고정되거나(Sticky), 와해 효과 후 강제 오버레이됨.
*   **디자인:** 검은색 배경에 사이언 블루의 얇고 미세한 그리드 패턴이 깔려있다. 좌우 모서리에는 끊임없이 **미약하게 진동하는 노이즈 라인(Subtle Noise Line)**을 배치한다.
*   **표시 내용 구조 (필수):** 단순 문구 금지. 다음 3가지 요소를 포함해야 함.
    1.  `[SYSTEM ERROR: CODE XXX-04B]` (가장 크게, 모노스페이스)
    2.  `Diagnosis Failed: Logical inconsistency detected in input sequence.` (경고 문구)
    3.  `Action Required: Consult Advanced Diagnostic Module.` (CTA 유도 텍스트)

### B. 사운드 디자인 스펙
*   **사운드 유형:** 디지털 아날로그 노이즈, 낮은 주파수의 불안정한 베이스톤.
*   **트리거 시퀀스:**
    1.  *(State 1 진입)*: 미세한 **'지지직-'** 하는 고주파수 필터링된 백색소음(White Noise) 시작. (볼륨: 낮게).
    2.  *(State 3 와해)*: 주파수가 급격히 하강하며, 불안정한 `삐-이잉...` 하는 **디튠(Detune)** 사운드가 발생. 이와 동시에 '시스템 경고음'을 낮은 볼륨으로 오버랩시킨다.
    3.  *(CTA 강제 유도)*: 모든 노이즈가 일순간 멈추며, 깊은 정적(Silence) 후, **낮고 권위적인 목소리 (Voice Over)**가 "진단 장치가 필요합니다."와 같은 메시지를 속삭이며 마무리한다.
