# 🗺️ Loss Aversion Funnel: 핵심 상호작용 흐름도 (Flowmap & Wireframe Blueprint)

## 🎯 목표 정의
사용자가 '구조적 결함'을 인식하는 순간(Trigger), 시스템의 위기감을 증폭시키고($L_{index}$ 노출), 결국 서비스 사용이 필수적이라고 느끼게 하여 다음 단계(Funnel 진입)로 강제 이동시키는 플로우를 설계합니다.

## ⚙️ I. 전체 상태 머신 (State Machine Diagram - Conceptual Flow)
| State ID | 사용자 행동/상황 | 시스템 반응 컴포넌트 | 출력 결과물 | 주요 목적 |
| :---: | :--- | :--- | :--- | :--- |
| **S0** | **(Entry)** 콘텐츠 소비 중 (관심 유발 단계) | 숏폼, 블로그, 영상 등 노출 지점 | 일반 정보/위기성 텍스트 | 문제 인식 및 주의 집중 |
| **S1** | **(Trigger)** 데이터 입력 필요 감지 (자체 진단 시작) | `[DataInputForm]` 컴포넌트 | 필수 정보 수집 UI | 행동 유도 (진단 참여) |
| **S2** | **(Process)** 데이터 전송 및 손실 계산 요청 | `API_CALL: CalculateLossIndex` | 로딩 화면 + 긴장감 고조 BGM/SFX | 시간 지연을 통한 기대 증폭 |
| **S3** | **(Crisis)** Loss Index 결과 수신 (최대 공포 노출) | `[LossIndexModal]` 컴포넌트 (레드 플래시, 경고 톤) | 손실 수치 ($L_{index}$) 및 위험 문구 | 공포 자극 극대화 (전환 동력) |
| **S4** | **(Solution)** 해결책 제시 (서비스 필연성 부여) | `[CTA_FunnelSection]` 컴포넌트 | Blueprint/워크시트 다운로드 CTA | 상품의 필요성 각인 및 전환 유도 |
| **S5** | **(Success)** 최종 리드 확보 완료 | 백엔드: CRM 연동 로직 + 감사 메시지 | "축하합니다. 다음 단계로 안내합니다." | 데이터 수집 및 퍼널 진입 성공 |

## 📐 II. 와이어프레임 상세 설계 (Component-Level Blueprint)

### A. State S1: [DataInputForm] - 정보 입력 단계
**목표:** 사용자가 자신의 데이터를 '손실 계산'에 기여하도록 유도한다.
*   **구성 요소:** 직군, 현재 보유 지식 레벨(슬라이더), 최근 3개월간의 프로젝트 시간 투입량 등 정량적/정성적 데이터 필드.
*   **핵심 로직:** 모든 입력 필드는 "이 데이터를 놓치면 발생하는 손실"이라는 문구와 연동되어야 합니다. (예: "현재 지식 레벨을 과소평가하는 것은 미래의 $L_{index}$를 키웁니다.")

### B. State S3: [LossIndexModal] - 공포 자극 단계 (Critical Component)
**목표:** 사용자에게 충격적인 손실 수치를 노출하고, 이 상태가 **'지금 당장 해결하지 않으면 안 되는 위기'**임을 인지시킨다.
*   **디자인 스펙:**
    1.  **배경:** `#FF3B30` (강렬한 경고색). 배경에 미세하게 깜빡이는 노이즈(Glitch Effect)를 적용하여 불안감을 조성한다.
    2.  **핵심 요소:** 중앙에 거대한 손실 지수 수치 ($L_{index}$)가 타이핑되듯 등장하며, 주변으로 '기회비용'과 '시간 낭비액'의 하위 항목이 연쇄적으로 폭발하듯이 표시되어야 한다.
    3.  **메시지:** "⚠️ 경고: 현재 구조적 결함 지수 $L_{index}$가 임계치를 초과했습니다. 이대로 방치할 경우, 잠재적 피해 금액은 최소 00원입니다." (구체적인 수치화 강조).

### C. State S4: [CTA_FunnelSection] - 해결책 제시 및 전환 유도 단계
**목표:** 손실 공포를 자극한 직후에, 서비스가 유일하고 필수적인 해결책임을 확정적으로 인지시킨다.
*   **구성 요소:**
    1.  **공감 (Problem Amplification):** "이 문제를 스스로 진단하기는 어렵습니다. 전문적 구조 분석이 필요합니다."
    2.  **솔루션 제시 (The Bridge):** 'Blueprint'를 핵심 솔루션으로 소개하며, 이것이 $L_{index}$의 근본 원인(구조 결함)을 해결해준다고 명시한다.
    3.  **CTA 버튼:** "나의 구조적 결함을 진단하고 Blueprint 받기 (무료/유료)" - 이 버튼은 가장 크고, 위급한 느낌을 주도록 디자인되어야 한다.

## ⚠️ III. 상호작용 로직 및 예외 처리 상세 정의 (Technical Logic & Error Handling)

가장 중요한 부분입니다. 시스템이 실패하더라도 공포감(Loss Aversion)은 절대 풀려서는 안 됩니다.

### 1. 성공 흐름 (Success Path: S3 $\rightarrow$ S4)
*   **조건:** $L_{index}$ 계산 성공 및 임계치 초과 ($\text{if } L_{new} > \text{Threshold}$)
*   **액션:** `LossIndexModal` 표시 $\rightarrow$ 사용자의 심리적 동요 유발 $\rightarrow$ `CTA_FunnelSection`으로 자연스러운 스크롤/전환 (강제 이동 느낌).

### 2. 예외 처리 흐름 A: API 호출 실패 (Failure Path: S2 $\rightarrow$ Error)
*   **원인:** 서버 응답 지연, 네트워크 오류 등 기술적 문제 발생.
*   **사용자 경험:** 로딩 스피너를 보여주는 대신, **'데이터 전송 중 연결 끊김(Connection Interrupted)'** 에러 모달을 띄워야 한다.
*   **공포 유지 로직:** "⚠️ 경고: 데이터를 안전하게 분석하는 과정에서 일시적인 문제가 발생했습니다. 이는 당신의 지식 습득 경로에 **치명적인 누락 정보가 존재함**을 의미합니다. 이대로 검색을 종료할 경우, 손실 추정치가 초기화되어 **진짜 피해 금액(Real Opportunity Cost)을 놓칠 위험**이 있습니다." (기술적 오류를 '정보 상실'이라는 공포로 재해석).
*   **재시도 버튼:** "안전한 연결로 다시 시도하기" (클릭 유도 유지).

### 3. 예외 처리 흐름 B: 사용자 입력 불완전 (Failure Path: S1 $\rightarrow$ Error)
*   **원인:** 필수 데이터 필드 미입력 또는 비정형적인 답변 제공.
*   **사용자 경험:** 경고 메시지 컴포넌트가 팝업된다.
*   **공포 유지 로직:** "🚨 **불완전한 진단은 위험합니다.** 몇 가지 핵심 정보를 빠뜨리셨습니다. 이 '정보의 공백(Context Gap)' 자체가 가장 큰 구조적 결함입니다. 이 간극을 채우지 못하면, 우리의 $L_{index}$ 측정 정확도에 오류가 생겨 오히려 **실제 손실액보다 적은 값**으로 위안받게 될 수 있습니다." (결과 자체를 신뢰할 수 없다는 공포 조성).
