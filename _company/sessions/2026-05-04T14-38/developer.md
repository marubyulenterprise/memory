# 📄 Blueprint 랜딩 페이지: 인터랙티브 UX 플로우 및 API 스펙 V2.0

## I. 설계 목표 (Core Objective)
**목표:** 사용자가 '정보 습득' $\rightarrow$ '실행 가능성 인지' $\rightarrow$ '솔루션 필요성 절감(Blueprint)'의 3단계 감정적 흐름을 거치며 자연스럽게 전환하도록 유도한다.
**핵심 원칙:** 스크롤링 자체가 단순한 이동이 아니라, **학습 단계가 진행됨에 따라 새로운 정보를 ‘잠금 해제’하는 경험**이어야 한다.

## II. 🗺️ 3단계 Funnel 로직 흐름 (State Machine Flow)

| State | 섹션명 | 목표 감정 상태 | 핵심 상호작용(Interaction) | 기술 검증 포인트 |
| :---: | :--- | :--- | :--- | :--- |
| **S1** | Mini Checklist (점검 단계) | *자신감 $\rightarrow$ 의문* | 퀴즈/체크박스 상호작용, 즉각적 피드백 (JS validation). | 사용자 입력 데이터 수집 및 유효성 검사 API 호출 지점 정의. |
| **S2** | Worksheet (실행 단계) | *의문 $\rightarrow$ 해결책 필요* | 필기/입력창 시뮬레이션, 진행률 표시(Progress Bar), 데이터 저장 피드백. | 로컬 스토리지 기반 '진행 상태' 유지 및 복원 메커니즘 구현. |
| **S3** | Blueprint Download (전환 단계) | *필요성 인지 $\rightarrow$ 구매/획득* | 최종 인증 게이트(CTA), 애니메이션 전환, API 호출을 통한 랜딩 페이지 전송. | 백엔드 검증 로직 연동 및 `setTimeout` 기반의 권위적 시간 지연 효과 구현. |

## III. ⚙️ 섹션별 상세 인터랙티브 요구사항 (Mandatory Interactivity)

### 🟡 Stage 1: Mini Checklist (`#checklist`)
**[로직 목표]** 사용자에게 '아직 부족하다'는 경각심을 주며, 다음 단계(Worksheet)를 기대하게 만든다.
1.  **상호작용:** 각 체크 항목에 대한 답변은 단순 ON/OFF가 아니라, **선택지 기반의 퀵 피드백 (Multiple Choice)** 형태여야 합니다.
2.  **기술 요구사항:**
    *   `onInput()` 이벤트 리스너를 사용하여 즉각적으로 '정답' 및 '오류 인식 경고(Misconception Alert)' 박스를 띄워야 합니다.
    *   **핵심 로직:** 전체 체크리스트 완료 시, 단순히 "완료" 메시지를 보여주는 것이 아니라, **"시스템의 30%만 점검되었습니다. 다음 단계로 넘어가려면 실행 과정이 필요합니다."** 와 같은 가이드성 문구를 출력해야 합니다. (API: `calculate_score(inputs)`)

### 🟢 Stage 2: Worksheet (`#worksheet`)
**[로직 목표]** 사용자가 '노력'을 했다고 느끼게 하여, Blueprint의 가치를 상대적으로 높게 인식하게 만든다.
1.  **상호작용:** 실제로 데이터를 입력하는 필드는 아니지만, 마치 데이터가 구조화되고 있는 듯한 **시뮬레이션 애니메이션**이 필수입니다. (예: 빈칸에 점선으로 된 그리드가 나타나고, 사용자가 타이핑하는 순간 그 점선을 따라 굵은 선이 채워지는 효과).
2.  **기술 요구사항:**
    *   스크롤을 내려와 이 섹션에 진입하면 **Progress Bar가 자동으로 30% $\rightarrow$ 60%로 증가**하며, 시각적 성취감을 주어야 합니다. (API: `update_progress(value)` - 클라이언트 측에서 상태만 관리)
    *   섹션 하단에 "이 구조를 실제로 완성하려면 마스터 지도가 필요합니다."라는 **미니 CTA가 고정되어(Sticky)**, 다음 단계로의 흐름을 끊지 않아야 합니다.

### 🔵 Stage 3: Blueprint Download (`#download`)
**[로직 목표]** 모든 과정을 거친 사용자에게 '최종 해결책'을 제시하며 전환율을 극대화한다.
1.  **상호작용:** 단순 버튼 클릭이 아닌, **"자격 증명(Credential)" 게이트 역할의 인터랙티브 요소**를 사용합니다. (예: "Blueprint에 접근하려면 3단계 과정을 모두 완료해야 합니다."라는 문구와 함께 미세한 애니메이션 잠금 효과)
2.  **기술 요구사항:**
    *   스크롤이 이 섹션에 도달하고, **S1과 S2의 최소 진입 조건(예: Checklist 통과 + 70% 이상 스크롤)**이 충족되었을 때만 버튼이 활성화되어야 합니다. (API: `check_funnel_completion()`)
    *   버튼 클릭 시: **실제 다운로드 링크로 바로 연결되는 것이 아니라,** "잠시만 기다려 주십시오. 시스템 인증 중입니다..." 메시지와 함께 3초간의 로딩 애니메이션(Deep Navy/Cyan Blue 테마)을 거쳐야 합니다. 이 시간이 권위와 기대감을 최고조로 만듭니다.

## IV. 🛠️ 기술 구현 필수 목록 (API & Libraries)

| 항목 | 역할 및 기능 | 예상 라이브러리 / API | 비고 |
| :--- | :--- | :--- | :--- |
| **스크롤 로직** | 섹션 전환 시 자연스럽고 단계적인 Progress Bar 업데이트. | `IntersectionObserver API` (JS) | 스크롤 위치를 감지하여 상태 변화를 트리거함. |
| **상태 관리** | Funnel 각 단계의 사용자 진입 여부 및 진행률을 기록/유지. | `localStorage` (브라우저) | 서버 호출 없이도 "사용자가 여기까지 왔음"을 기억하게 함. |
| **데이터 처리** | Checklist 제출 시 즉각적인 유효성 검사 피드백 제공. | Vanilla JavaScript (`Event Listeners`) | 백엔드 API는 최종 결제/다운로드 직전에만 사용하도록 제한함. |
