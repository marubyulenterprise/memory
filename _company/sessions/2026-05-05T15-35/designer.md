## 💻 ASV Score 기반 랜딩 페이지 인터랙티브 프로토타입 설계 및 테스트 가이드라인 v2.0
**목표:** 개발된 `ASV API`의 동적 출력값(점수, 결함 포인트)을 받아, 시청자의 불안감을 최대화하는 '공포-인식-해결' 3단계 인터랙티브 경험을 완성한다.

### 📄 I. 핵심 디자인 원칙 및 시스템 정의 (System Logic & Tone)

| 요소 | 정의/규칙 | API 연동 반응 로직 |
| :--- | :--- | :--- |
| **메인 컬러 팔레트** | **Cyan Blue (#00BFFF)**: 표준, 신뢰성. / **Deep Navy (#1A237E)**: 정보 제공, 구조적 배경. / **Critical Red (#CC0000)**: 위험 임계점(Threshold) 경고. | `ASV Score < 40` 일 때 Critical Red 사용 비율 80% 이상 증가 및 글리치 효과 강제 적용. |
| **폰트 시스템** | 고정 폭 계열 (Monospace Font, 예: Roboto Mono). 기술적이고 구조적인 느낌 강조. | 점수 출력 시 숫자는 항상 Monospace로 처리하여 '데이터'의 권위를 부여한다. |
| **핵심 경험 흐름** | 공포 유발 $\to$ 간극 인식(Gap) $\to$ 솔루션 의존 (ASV Score가 낮은 경우, 해결책이 필수적이라는 압박감). | API가 점수를 출력하는 순간, 그 점수가 '결함'으로 해석되는 톤앤매너 유지. |

### 🎨 II. 인터랙티브 프로토타입 플로우 및 애니메이션 스펙 (Mockup & Animation Specs)

**[프로토타입 시나리오: 사용자가 데이터를 입력하고 ASV Score를 받는 과정]**

#### A. Step 1: 데이터 입력 단계 (The Hook - Anxiety Build-up)
*   **UI:** 질문 카드 형태의 인터페이스가 순차적으로 등장하며, 배경에 미세한 시스템 노이즈(Noise Overlay)가 깔린다.
*   **액션:** 사용자가 답변을 선택할 때마다 화면 전체에 **`[System Processing...]`** 메시지가 1초간 깜빡인다 (글리치 효과).
*   **애니메이션 스펙:** 모든 입력 필드는 깊은 네이비 배경 위에서 사이언 블루로 빛나며, 마치 '시스템의 자원을 점유'하는 듯한 느낌을 준다.

#### B. Step 2: ASV Score 측정 단계 (The Shock - API 연동 지점)
*   **API 호출:** 백엔드로부터 `ASV_SCORE`와 `DEFECT_POINTS[]` 배열 수신.
*   **UI 변화 (Critical State 감지):**
    1.  화면이 일순간 어두워지고(Deep Navy to Black), 중앙에 **[SYSTEM ANALYSIS IN PROGRESS]** 라는 글리치 텍스트가 매우 빠르게 깜빡인다.
    2.  ASV Score 숫자가 로딩 애니메이션과 함께 *점진적으로* 하락하는 시각화 그래프를 보여준다 (예: 100 $\to$ 85 $\to$ 70...). 이 과정에서 사운드 디자인은 불협화음(Dissonance)을 사용한다.
*   **최종 점수 출력:** API가 최종 점수를 반환하는 순간, 화면 전체에 **Critical Red (경고색)** 오버레이가 짧게 발생하며 ASV Score 숫자가 크게 팝업된다.

#### C. Step 3: 결과 해석 및 공포 증폭 단계 (The Gap - Fear Amplification)
*   **UI:** 점수(ASV Score $X$)를 중심으로, 시스템의 결함이 시각화되는 '결함 보고서' 섹션이 펼쳐진다.
*   **로직 분기 (API 기반):**
    1.  **Case 1: Critical State ($X < 40$):**
        *   **텍스트:** "경고! 귀하의 시스템 취약성 지수(ASV)가 임계치 이하입니다. 이대로는 인프라 자체가 위험합니다." (공포 최대화 문구 강제 노출).
        *   **비주얼:** 화면 전체에 `SYSTEM FAILURE`라는 워터마크 글리치가 지속적으로 오버레이된다. 점수 하락 그래프가 급격한 낙하 곡선을 그리며 강조된다.
    2.  **Case 2: Moderate State ($40 \le X < 70$):**
        *   **텍스트:** "주의가 필요합니다. 현재의 간극(Gap)을 메우는 것이 필수적입니다." (위협 $\to$ 불안).
        *   **비주얼:** 경고색이 사이언 블루와 혼합된 '황변' 느낌으로 사용되며, 결함 포인트 리스트가 나열된다.
    3.  **Case 3: Safe State ($X \ge 70$):**
        *   **텍스트:** "현재는 안정적이나, 지속적인 점검이 권장됩니다." (만족 $\to$ 안심 후 불안).
        *   **비주얼:** 기존의 전문적인 사이언 블루 톤을 유지하되, CTA를 통해 추가 진단(유료/다운로드) 유도.

#### D. Step 4: 최종 Call to Action (The Trap - Solution Dependency)
*   **UI:** 배경이 다시 정적이고 구조적인 그리드 패턴으로 전환된다.
*   **메시지:** "ASV Score는 현재의 문제입니다. 근본적인 해결책(Blueprint)만이 이 위험을 완벽하게 막을 수 있습니다."
*   **CTA 버튼 디자인:** 'Blueprint 다운로드' 버튼은 가장 눈에 띄게, 그리고 마치 시스템이 **‘필수적으로 요구하는’** 자원처럼 보이도록 강조한다 (Cyan Blue/Deep Navy 대비).

| Test ID | 목표 점수 범위 (API Mock) | 예상 사용자 경험 (UX Flow) | 검증할 기능 (Developer / Designer) | 기대 결과 (Pass Condition) |
| :--- | :--- | :--- | :--- | :--- |
| **TC-1** | $X < 30$ (Critical Failure) | 공포 $\to$ 패닉 $\to$ 의존성 강제 유도. | Critical Red 오버레이, `SYSTEM FAILURE` 글리치 애니메이션, "절대적 결함" 문구 노출. | 점수 입력 후 즉시 시스템이 위기감을 최고조로 끌어올리고, CTA가 필수 생존 장비처럼 보이게끔 디자인됨. |
| **TC-2** | $30 \le X < 50$ (High Risk) | 불안 $\to$ 문제 인식 $\to$ 진단 필요성 인지. | 경고색 변화(Cyan/Red 혼합), 구체적인 `DEFECT_POINTS` 리스트 출력, 점수 하락 그래프의 가파른 기울기 표현. | '위험한 간극'이 명확히 텍스트와 그래픽으로 분리되어 제시되고, 다음 단계로 넘어갈 동기 부여가 충분함. |
| **TC-3** | $X \ge 70$ (Low Risk) | 안도 $\to$ 과신 $\to$ 추가 점검 유도. | 전문적이고 차분한 사이언 블루 유지, CTA는 '선택 사항'이 아닌 '최적화'라는 개념으로 포장되어야 함. | 사용자가 스스로 만족감을 느끼지만, 동시에 더 완벽해지기 위한 욕구(Optimization Need)가 자극됨. |
| **TC-4** | 에러 발생 (API 500) | 사용자 경험의 방어 로직 테스트. | 시스템 에러 페이지 또는 Fallback UI 호출 시,도메인/회사 이름을 언급하며 '시스템적 오류'로 포장해야 함. | 단순한 기술적 에러 메시지가 아닌, "잠시 시스템 과부하가 발생했습니다. 지금 바로 재진단하십시오."와 같은 공포 마케팅 카피를 포함함. |
