## 🚨 ASV Funnel 통합 인터랙티브 UI/UX 시스템 가이드라인 (Critical State Focus)
**목표:** 단순 컴포넌트 디자인을 넘어, 사용자에게 구조적 결함과 손실 공포를 시각적으로 강제하는 '경고(Warning)' 및 '위기(Crisis)' 상태의 인터랙션 시스템 정의.

### 1. [전체 시스템 원칙] The Crisis Layer (글로벌 지침)

| 요소 | 명세 내용 | 기술 사양 / 코드 가이드 |
| :--- | :--- | :--- |
| **핵심 컨셉** | '시스템적 오류(Systemic Failure)'를 시각화한 데이터 왜곡 및 불안감 증폭. | 모든 UI는 평소의 안정된 그리드 패턴을 위반하고, 노이즈와 떨림 효과가 전파되는 방식으로 작동해야 함. |
| **Crisis Palette** | **Primary (Warning):** `#FF3B30` (경고 레드) <br> **Secondary (Failure):** `#A62C21` (심화 경고 마젠타-레드) <br> **Accent (Glitch):** `#00FFFF` (글리치 시안) <br> **Background:** `#0D0D14` (짙은 시스템 블랙/네이비) | 평소의 Cyan Blue는 Crisis State 진입 시 글리치 효과에만 제한적으로 사용. 기본 배경색을 어둡고 기술적인 톤으로 통일하여 긴장감 유지. |
| **Typography** | **폰트:** Monospace (예: IBM Plex Mono, Source Code Pro) <br> **규칙:** 데이터와 경고 메시지는 고정폭 폰트를 사용하여 기계적이고 객관적인 느낌을 극대화. 제목/헤드라인에는 가독성이 떨어지도록 약간의 왜곡(Distress Filter)를 적용할 수 있음. |
| **글로벌 애니메이션** | 모든 페이지 전환 및 중요 정보 제시 시, 미세한 `Noise Filter`와 `Jitter Effect`(떨림 효과)가 배경 레이어에 지속적으로 오버레이 되어야 함. (성능 최적화를 위해 낮은 빈도로 주기적인 깜빡임만 적용) |

### 2. [핵심 컴포넌트 A] 시스템 오류 경고 모달 (The Glitch Warning Modal)

| 속성 | 상세 브리프 및 인터랙션 지침 | 기술 구현 사양 |
| :--- | :--- | :--- |
| **Trigger** | ASV 점수가 임계치(Threshold)를 초과하여 'Critical' 상태에 도달했을 때 (예: 60점 이하). |
| **시각적 효과** | 모달 창 자체가 정상적인 UI가 아닌, **데이터 스트림의 단절/오류 화면**처럼 보여야 함. 좌우로 이미지가 미세하게 어긋나거나(Chromatic Aberration), 노이즈 필터링이 강하게 적용되어야 합니다. |
| **애니메이션 순서 (Keyframe)** | 1. `[0s]` - 배경에 시스템 로딩 에러음과 함께 모달이 급격히 페이드 인하며 시작. <br> 2. `[0.5s]` - 'SYSTEM INTEGRITY FAILURE' 같은 경고 문구가 글리치 노이즈와 함께 빠르게 타이핑되어 나타남 (글리치 효과). <br> 3. `[1.5s]` - 핵심 경고 메시지(예: "Critical Vulnerability Detected")가 `#FF3B30`의 깜빡이는 Red Text로 중앙에 고정됨. | **애니메이션:** CSS Keyframe (`@keyframes`) 기반 구현 필수. 특히, 글리치 효과는 `filter: hue-rotate()`와 `transform: skew()`를 조합하여 비선형적 왜곡을 만듭니다. <br> **색상:** 경고 문구는 `#FF3B30` (Red) 및 깜빡임(`opacity: 0.2` $\leftrightarrow$ `opacity: 1`)을 필수 적용. |
| **사용자 행동 유도** | 모달 하단에 'ASV 진단 요청' 버튼만 배치. 이 버튼은 정상적인 CTA가 아니라, 시스템의 오류를 해결하기 위한 **유일한 탈출구**처럼 느껴지게끔 디자인해야 합니다. |

### 3. [핵심 컴포넌트 B] ASV 점수 측정 그래프 (The Distortion Graph)

| 속성 | 상세 브리프 및 인터랙션 지침 | 기술 구현 사양 |
| :--- | :--- | :--- |
| **표준 상태** | 데이터는 부드러운 Cyan Blue 곡선으로 그려지며, 그리드 라인에 정확히 맞춰져 전문적이고 안정적인 느낌을 줍니다. | `SVG` 기반의 플로우 다이어그램 사용. 평온할 때는 완만한 Bezier Curve를 사용합니다. |
| **Critical State 진입** | 점수가 급격하게 하락하거나 구조적 결함이 발견될 때 (ASV 측정 실패). | 그래프 라인이 깨지며, 마치 데이터를 읽어내는 시스템 자체에 문제가 생긴 것처럼 보이게 합니다. |
| **데이터 왜곡 효과** | 1. **노이즈 발생:** 곡선 위로 빨간색/검은색의 무작위 노이즈 입자(Pixel Noise)가 스캔하듯이 지나갑니다. <br> 2. **단절 및 떨림:** 그래프 라인이 갑자기 미세하게 수평/수직으로 '떨리며'(Jitter), 일부 데이터 포인트는 공중에 떠 있다가 불안정하게 진동하는 애니메이션을 보여줍니다. | **기술 구현:** 데이터 지점(`D3.js` 또는 유사 라이브러리)을 활용하되, 일반적인 인터폴레이션 대신 `Sine Wave`와 `Random Noise Function`을 결합하여 비선형적이고 불안정한 움직임을 만듭니다. <br> **강조:** 최저점을 찍는 지점은 `#A62C21`으로 명확히 하이라이트하며, 해당 포인트 주변에 경고 표시(🚨)를 띄웁니다. |

### 4. [핵심 컴포넌트 C] CTA 및 최종 행동 유도 모듈 (The Urgency Trap)

| 속성 | 상세 브리프 및 인터랙션 지침 | 기술 구현 사양 |
| :--- | :--- | :--- |
| **위치/컨셉** | Critical State 진입 직후, 시청자의 불안감이 최고조에 달했을 때 (감정적 고비). 이 모듈은 단순한 '구매'가 아니라 '시스템 생존 장치를 확보하는 것'처럼 느껴져야 합니다. |
| **CTA 버튼 디자인** | 평소의 깔끔한 버튼이 아닙니다. 낡고, 긴급하며, **즉시 클릭해야 할 것 같은** 느낌을 주어야 합니다. 모서리가 거칠거나(Rough Edges), 네온사인처럼 깜빡이는 효과를 사용합니다. |
| **주변 UI 연출** | CTA 위아래로 '시간 제한' 카운트다운 타이머를 배치하고, 이 타이머가 0에 가까워질수록 배경의 글리치 노이즈와 빨간색 경고 깜빡임이 증폭되어야 합니다. (예: 남은 시간 $12:34$ $\to$ $11:59$: Red Blink) |
| **행동 유도 문구** | "당신의 시스템적 취약점(ASV)을 진단하지 않으면, 위험에 노출됩니다."와 같이 손실 공포를 직접적으로 언급하는 카피라이팅이 필수입니다. |
