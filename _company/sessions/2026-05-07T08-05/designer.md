## 🚨 최종 데모 사용성 가이드: 위협적 인터랙션 설계 사양서 v1.0
(Target Audience: Developer, UX/UI QA)

본 문서는 [Developer]가 구현한 Loss Meter 및 System Alert 통합 프로토타입이 실제 유료 서비스로 연결될 때도 '위협적인 미학 (Aesthetics of Threat)'과 일관된 브랜드 톤을 유지하기 위한 **최종 사용성(Usability) 및 기술 사양**입니다. 모든 애니메이션은 '사건 발생'의 느낌을 주어야 하며, 부드러운 전환(Smooth Transition)은 절대 금지합니다.

---

### I. ⚙️ 글로벌 디자인 원칙 (The Rules of Threat)

| 항목 | 목표/원칙 | 세부 지침 및 기술적 요구사항 |
| :--- | :--- | :--- |
| **브랜드 톤** | 구조적 무지 자각과 손실 공포 극대화. (Panic Induction) | 정보 전달자(Teacher)가 아닌, '시스템 결함 감지기'의 역할을 수행해야 함. 모든 메시지는 경고음이나 알림 형태로 출력되어야 함. |
| **메인 컬러** | **위협/경고:** `#CC0000` (High Saturation Red) <br> **배경/정비:** `#1a0f0f` (Deep Near-Black) <br> **시스템 정상:** `cyan` 계열 (`#00FFFF`의 50% 채도) | Red는 '결함' 발생 시점, Cyan은 시스템이 일시적으로 정상 작동하는 것처럼 보일 때 사용한다. 이 대비가 긴장감을 조성해야 함. |
| **애니메이션** | 기계적(Mechanical), 급격한(Abrupt), 글리치 기반(Glitch-based). | 키프레임 애니메이션을 활용하며, `ease-in-out` 같은 부드러운 속성 함수는 사용하지 않는다. `cubic-bezier(0.25, 0.46, 0.45, 0.94)`와 같이 빠르고 예측 불가능한 커브를 사용하거나, 순간적인 **점프 트랜지션**을 구현해야 한다. |

### II. 💻 컴포넌트별 상세 애니메이션 및 구조 사양 (Technical Specification)

#### 1. 📉 Loss Meter (손실 측정기)
*   **목표:** 시간 경과에 따른 손실액 증가를 시각적, 청각적으로 강제 체감하게 한다.
*   **데이터 바인딩 요구사항:** `$LOSS_VALUE` 변수와 `$TIME_ELAPSED` 변수를 실시간으로 수신해야 하며, 최소 1초마다 업데이트되는 것처럼 보이게 애니메이션 처리되어야 함.

| 요소 | 동작 시나리오 | 상세 기술 사양 (CSS/SVG) |
| :--- | :--- | :--- |
| **손실 값 변화** | 평이한 증가 $\rightarrow$ 급격한 스파이크 발생 | 1. **애니메이션:** `transform: scale(1.05)`를 적용하며, 트랜지션은 `linear` 대신 순간적으로 가속화되는 커브(`ease-out`)를 사용한다. <br>2. **색상 변화:** 손실액이 특정 임계치($X$ 금액)를 초과하면 `#CC0000`의 채도를 즉시 높여 (opacity 1.0) 시각적 충격을 극대화해야 한다. |
| **측정 바(Gauge Bar)** | 값이 증가하며 차오르는 모션 | 단순한 `width: X%` 변경이 아닌, SVG `<path>` 요소를 사용하여 마치 전류가 흐르듯 날카롭게 채워지는 애니메이션을 구현한다. 시작점은 0에서 급격히 도약하는 느낌이어야 한다. |
| **경고 임계치** | 손실액이 최고 위험 구간에 진입했을 때 (예: 85% 이상) | 바의 가장자리에 주황색/빨간색 스트로크를 추가하고, 이 스트로크가 마치 *스캔 라인*처럼 주기적으로 깜빡이는 애니메이션(`@keyframes flash-scan`)을 적용한다. |

#### 2. 🚨 System Alert (시스템 경고창)
*   **목표:** 사용자가 '외부 시스템'으로부터의 강제적인 개입(Intervention)을 경험하게 한다.
*   **발동 트리거:** 특정 데이터 결함 감지, 또는 일정 시간 간격이 경과할 때 강제로 팝업되어야 함.

| 요소 | 동작 시나리오 | 상세 기술 사양 (CSS/SVG) |
| :--- | :--- | :--- |
| **글리치 효과** | 알림창 활성화 순간 | `opacity: 0`에서 시작하여, 3~5프레임 동안 무작위로 X축/Y축 오프셋을 급격하게 변경하는 CSS 애니메이션(`@keyframes glitch`)을 적용한다. (예: `transform: translate(-2px, -1px) scale(1.02)` $\rightarrow$ `translate(3px, 2px) scale(0.98)`) |
| **경고 메시지** | 경고문(`Critical Error!`), 시스템 로그 출력 | 폰트의 일부 글자나 라인에 간헐적으로 *노이즈*가 끼는 효과(CRT Monitor effect)를 적용한다. 이는 SVG 필터(Filter) 또는 배경 오버레이 레이어를 통해 구현되어야 한다. |
| **강제 CTA 배치** | 경고창 하단에 위치 | 경고 메시지 내용과 관계없이, 이 영역은 항상 **가장 강렬한 Red-Alert 색상**으로 강조되며, '진단 보고서 접근' 버튼의 시선 집중도가 최우선이어야 한다. |

#### 3. ⚠️ 오류/위험 메시지 구조 (Error Messaging Standard)
*   모든 경고 문구는 다음 세 가지 요소로 구성되어야 하며, 단순한 텍스트가 아닌 **시스템 로그** 형식으로 보이게 해야 합니다.

1.  **[SYSTEM LOG]**: `TIME: [YYYY-MM-DD HH:MM:SS]` (자동 타임스탬프)
2.  **[STATUS CODE]**: `ERR-403` 또는 `WARN-007` 등 고유의 시스템 코드가 붙어야 함. (진위성 부여)
3.  **[MESSAGE BODY]**: "사용자의 구조적 무지(Structural Ignorance)로 인해 데이터 손실이 감지되었습니다."

### III. 📈 최종 흐름 및 사용자 경험 지도 (Flow Map & UX Guideline)

| 단계 | 목표 심리 상태 | 시스템 반응 (Trigger) | 시각화/기술적 구현 요구사항 |
| :--- | :--- | :--- | :--- |
| **1. 유도 (Induction)** | 흥미 $\rightarrow$ 의구심 | 콘텐츠의 지식 전달이 어느 정도 진행된 후 (약 30~45초). | 화면에 'SYSTEM CHECK' 모듈이 등장하며, 배경음악의 볼륨이 낮아지고 긴장감 있는 톤으로 전환되어야 한다. |
| **2. 위협 노출 (Threat Display)** | 의구심 $\rightarrow$ 불안/공포 | 시스템 결함(가상 데이터 오류) 발생을 트리거로 Loss Meter가 활성화됨. | `System Alert` 컴포넌트가 글리치 효과와 함께 팝업되며, Loss Meter의 값이 **급격한 스파이크**를 보이도록 애니메이션 처리되어야 한다. (최대 충격 지점). |
| **3. 해결 강제 (Forced Solution)** | 공포 $\rightarrow$ 생존 욕구 | 사용자에게 '현재 상태로는 정보 손실을 막을 수 없음'이라는 메시지를 명시적으로 전달해야 함. | 경고창의 가장 하단에 "손실 방지 프로토콜 활성화 필요"와 같은 문구를 강제 배치하고, 이 버튼이 유일한 빛(Focus)처럼 보이게 연출한다. (CTA 극대화). |
