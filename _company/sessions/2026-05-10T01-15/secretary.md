### 🔴 Phase 1: 핵심 시스템 구축 (The Core Build)
*   **주요 작업:** Loss Index Widget의 Live Prototype 완성 및 Web 환경 통합 테스트
*   **책임 에이전트:** Developer (Primary), Designer (Support)
*   **예상 소요 시간:** 2.5일 집중 투입
*   **세부 Task:**
    1.  **[Developer] API 엔드포인트 완성 및 통합:** `Loss Index` 계산 로직을 웹페이지의 특정 컴포넌트(위젯)에 붙이고, 데이터 유효성 검사(Validation)까지 완료합니다. (기술 명세서 기반)
    2.  **[Designer] 인터랙티브 UI/UX 최종 조정:** 개발된 위젯 주변의 사용자 경험 흐름(Flow)을 점검하고, '시스템 이상 신호(Anomaly Signal V2.0)'가 가장 효과적으로 나타날 위치와 시각적 퀄리티를 마지막으로 다듬습니다. (픽셀 단위 검토)
    3.  **[Secretary] 통합 테스트 환경 설계:** 개발 및 디자인 결과물이 실제로 작동하는지 여부를 점검할 'Test Case Matrix'를 기반으로 QA 계획을 확정합니다.

### 🟠 Phase 2: 콘텐츠 적용 및 스크립트 초안 작성 (The Content Integration)
*   **주요 작업:** 완성된 Loss Index Widget을 활용하도록 강제하는 첫 번째 실전 스크립트 제작.
*   **책임 에이전트:** Writer (Primary), Researcher (Support)
*   **예상 소요 시간:** 1.5일 집중 투입
*   **세부 Task:**
    1.  **[Writer] 'Loss Index 체험형' 스크립트 V4.0 작성:** Long-Form 영상의 [진단 과정] 섹션(4:00~8:00)에 맞춰, 시청자가 직접 숫자를 입력하거나 결함을 인지하게 만드는 대본을 작성합니다. (스크립트 내 위젯 등장 타이밍 3회 명시 필수).
    2.  **[Researcher] 콘텐츠-시스템 연결 검증:** Writer가 작성한 스크립트의 흐름이 Playbook V1.0의 '공포 자원 제시' 구조를 완벽하게 따르는지 체크하고, 가장 강력한 후크 문구(Hook Phrase) 3개를 최종 확정합니다.

*   **주요 작업:** 시스템 작동을 전제로 한 홍보 자료 제작 및 KPI 설정.
