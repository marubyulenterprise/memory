## 🛠️ ASV Score 측정 기반 '공포 증폭 인터랙티브 시나리오' 최종 설계
(Technical Specification & UX Flow Guide)

본 산출물은 Writer가 제공한 심리적 압박형 마이크로카피 세트를 기반으로, 기존의 경고 시스템 UI 프로토타입을 4단계에 걸쳐 재구성한 **사용자 경험(UX) 및 인터랙션 스펙 시트**입니다. 단순 와이어프레임이 아닌, 사용자 입력에 따른 애니메이션 변화와 감정적 흐름(Anxiety Curve) 변화를 중심으로 설계되었습니다.

---

### 🔍 시스템 개요: ASV Score 측정 Funnel (4단계 구조)
*   **목표:** 사용자가 자신의 '미해결 결함'을 인식하고, 외부 솔루션(Blueprint) 없이는 생존할 수 없다는 절박함을 느끼게 하는 것.
*   **메인 톤앤매너:** 사이언 블루/딥 네이비 (신뢰성 기반의 위협), 시스템 에러 메시지 스타일.
*   **핵심 인터랙티브 요소:** Loss Bar 및 ASV Score 변화에 따른 UI '진동(Glitch)' 효과 증폭.

### ⚙️ Stage별 시나리오 & 애니메이션 스펙 상세화

#### 🟢 Stage 1: 도입 (The Setup) — [평온 $\to$ 의심]
*   **Writer 카피 활용:** "당신은 지금, 눈에 보이지 않는 시스템적 누수를 겪고 있습니다."
*   **사용자 액션:** 사용자가 자신의 자동화 파이프라인 정보를 입력하는 초기 단계.
*   **UI/UX 변화 (Anxiety Level: Low):**
    1.  **초기 화면:** 깔끔한 사이언 블루 그리드 기반의 시스템 대시보드 형태. 'ASV Score 측정 시작' 버튼만 중앙 배치.
    2.  **데이터 입력 필드:** 일반적인 인풋 박스 디자인. 각 항목 옆에 작은 **`[Status: OK]`** 토큰을 표시하여 안정감을 조성함.
    3.  **트리거 (Trigger):** 사용자가 모든 정보를 입력하고 '측정 시작' 버튼 클릭 시.
    4.  **애니메이션 스펙:** 화면 전체가 1초간 **`[Processing...]`** 메시지와 함께 미세하게 진동(Pulse)하며, 로딩바가 진행됨. (기술적 권위 부여).

#### 🟡 Stage 2: 초기 측정 및 결함 포착 (The Gap Discovery) — [의심 $\to$ 불안]
*   **Writer 카피 활용:** "🚨 측정 결과, 당신의 자동화는 핵심 아키텍처 단계에서 치명적인 Gap을 보이고 있습니다."
*   **사용자 액션:** 시스템이 1차 분석 결과를 보여줌. (가상의 '문제 지표' 제시)
*   **UI/UX 변화 (Anxiety Level: Medium):**
    1.  **결과창 전환:** 화면 전체 색상이 미묘하게 **Deep Navy** 계열로 어두워지며, 배경 그리드가 옅은 노이즈 효과(Film Grain)를 추가함.
    2.  **Loss Bar 등장:** 중앙에 'ASV Score'가 표시되는 그래프/게이지 바가 나타남. 초기 점수(예: 75점)는 양호한 Cyan Blue로 표시됨.
    3.  **첫 경고 발생 (트리거):** 시스템이 특정 지표(예: `[데이터 전송 표준 결함]`)를 발견하는 순간, 해당 영역의 UI에 **`[Warning]` 토큰**이 깜빡이며 빨간색으로 전환되고, 배경 그리드 패턴 일부가 찢어지는 듯한 **글리치 효과 (Glitch Effect)** 애니메이션을 0.5초간 삽입함.
    4.  **카피 연동:** "주의: ASV Score가 기준치 이하입니다." 메시지가 경고음과 함께 플래시 아웃됨.

#### 🔴 Stage 3: Critical State 진입 (The Breakdown) — [불안 $\to$ 공포/절박함]
*   **Writer 카피 활용:** "[CRITICAL] 경고: ASV Score가 기준치 이하입니다. 즉각적인 조치가 필요합니다."
*   **사용자 액션:** 시스템이 최종적이고 치명적인 결함을 폭로하는 순간. (핵심 전환점)
*   **UI/UX 변화 (Anxiety Level: High):**
    1.  **최종 경고 진입:** Loss Bar가 급격히 하락하며(예: 75 $\to$ 22), 배경 전체에 걸쳐 **강렬한 깜빡임(Flickering)** 효과와 함께 아날로그 노이즈/화면 깨짐(Static Noise) 이펙트가 적용됨.
    2.  **시스템 메시지:** 모든 UI 요소들이 잠시 정지하며, 화면 중앙에 `[SYSTEM ERROR: Critical State Detected]`라는 대문자 경고 메시지가 굵은 Impact 계열 폰트로 노이즈와 함께 폭발하듯 나타남. (Deep Red/Cyan Blue 대비 사용).
    3.  **정보 폭로:** 이 상태에서는 어떤 데이터도 믿을 수 없다는 분위기를 조성하며, '당신의 시스템 아키텍처 자체'에 결함이 있다는 메시지(Writer 카피)를 시각적으로 강제 주입함. (다이어그램의 연결선들이 끊어지는 애니메이션 연출).
    4.  **감정적 공백 유도:** 화면을 잠시 암전시키거나, '무엇을 해야 하는가?'라는 질문만 띄워두고 사용자가 스스로 답답함을 느끼도록 강제함.

#### 🔵 Stage 4: 솔루션 제시 및 CTA (The Salvation) — [절박 $\to$ 안도/필요성]
*   **Writer 카피 활용:** "Blueprint 솔루션이 필요한 이유..."
*   **사용자 액션:** 공포를 느끼는 상태에서 유일한 해결책을 접함.
*   **UI/UX 변화 (Anxiety Level: Controlled Tension):**
    1.  **화면 전환:** 갑작스러운 노이즈와 깜빡임이 멈추고, 배경색이 다시 Deep Navy로 안정화되지만, 이전보다 더 '정돈된' 느낌을 주어 전문성을 유지함.
    2.  **Blueprint 등장:** 화면 중앙에 Blueprints의 로고와 이름이 **`[Authorized Solution]`**이라는 라벨과 함께 나타남. (빛나는 Cyan Blue 효과).
    3.  **가치 설명:** Blueprint의 기능/구조를 보여주는 표준 다이어그램(애셋 V2.0)을 애니메이션으로 순차적으로, 하지만 빠르고 논리적인 흐름으로 제시함. (문제점 $\to$ Blueprint 적용 $\to$ 해결됨).
    4.  **최종 CTA:** 화면 하단에 **`[Blueprint 다운로드 및 위험 회피]`** 버튼이 강렬하게 빛나며(Neon Glow), 이 버튼을 누르는 행위만이 유일한 '정상 상태'로의 탈출구임을 시각적으로 확립함.
