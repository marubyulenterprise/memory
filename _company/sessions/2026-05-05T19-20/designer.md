## ⚙️ ASV 진단 결과 페이지 Design System Specification (v3.0)
*개발자 즉시 구현 가능한 인터랙티브 컴포넌트 및 로직 가이드라인 제공*

본 디자인 시스템은 단순한 와이어프레임을 넘어, **사용자가 '시스템적 결함'을 경험하도록 유도하는 상호작용(Interaction)**에 초점을 맞추었습니다. 모든 컴포넌트는 Mock API 데이터 연동을 전제로 하며, 다음의 핵심 원칙을 따릅니다: *경고성 (Warning Tone)* $\to$ *구조적 (Systematic Look)* $\to$ *불안감 증폭 (Anxiety Focus)*.

---

### 1. [핵심 모듈] ASV Score 디스플레이 (The Vulnerability Gauge)
사용자가 진단 결과를 마주하는 순간, 시각적으로 압도적인 공포를 유발해야 합니다.

| 요소 | 스펙/디자인 가이드라인 | 인터랙션 로직 (개발 지침) |
| :--- | :--- | :--- |
| **메인 점수 표시** | 폰트: *Monospace* (예: Courier Prime), 크기: 96pt. 색상: `#CC3300` (Critical Red). 배경: 반투명 어두운 그리드 패턴 (`rgba(15, 25, 45, 0.8)`). | **[애니메이션]:** 페이지 로딩 시 `COUNTUP` 애니메이션 적용. 점수가 표시되는 동안 미세한 **글리치 노이즈 필터**가 오버레이되어야 합니다. (빈도: 1초에 2회) |
| **경고 상태 바** | 제목: "CRITICAL SYSTEM ALERT". 배경색: `#FFC800` $\to$ `#CC3300`. 형태: 시스템 오류 메시지 창 (`<div class="glitch-box">`). | **[상태 변화]:** ASV 점수가 임계점(예: 65점 이상)을 넘으면, 경고창이 화면 전체를 덮으며 `글리치 노이즈`와 함께 부드럽게 나타나야 합니다. (진동/사운드 연출 필수). |
| **데이터 출처 명시** | 작은 글씨로 하단에 배치: "Data Source: LMI Gap Analysis Engine v2.1". 색상: `#80BFFF` (Cyan Blue). | *고정 텍스트.* 권위적인 느낌을 주기 위해 자그마하게 배치하며, 마우스 오버 시 출처 데이터의 복잡한 그래프가 순간적으로 플래시되는 효과를 추가합니다. |

### 2. [진단 결과 섹션] 구조적 취약성 분석 (The Gap Visualizer)
측정된 점수를 단순 수치가 아닌 '결함 부채'로 인식시켜야 합니다.

| 요소 | 스펙/디자인 가이드라인 | 인터랙션 로직 (개발 지침) |
| :--- | :--- | :--- |
| **레벨별 그래프** | 형태: 3차원 계층적 파이 차트가 아닌, **겹치는 그리드 기반의 시계열 히스토그램** 사용. 색상: 취약한 영역은 `Deep Navy` (불안감), 안전한 영역은 `Cyan Blue` (희미함). | **[API 연동]:** 백엔드 API로부터 3~5개의 핵심 결함 지표(예: Focus Deficit, Resource Gap)를 받아와야 합니다. 이 지표들이 순차적으로 그래프에 그려지는 애니메이션이 필수입니다. |
| **핵심 결함 정의 카드** | 3개 배치. 제목: `[DEFECT AREA]`, 서브 헤드라인: "당신의 시스템에서 발견된 구조적 취약성". 배경: 어두운 계조의 모듈 박스. | **[호버 효과]:** 마우스 오버 시, 해당 결함이 '시스템적으로 폭로되는' 듯한 `데이터 스캔(Scanline)` 애니메이션과 함께 설명 텍스트가 증폭되어야 합니다. (예: 노이즈 필터와 함께 글자가 떨림). |
| **비교/분석 모듈** | 제목: "평균 사용자 시스템과의 결함 격차". 시각화: 사용자의 ASV 점수(빨간색)와 일반 평균(파란색)을 비교하는 *좌우 분리형 막대 그래프*. | **[시각적 강조]:** 두 값의 차이가 클수록, 그 간극 부분에 'SYSTEM FAILURE'를 상징하는 붉은 전기 아크 또는 글리치 라인이 표시되어야 합니다. (이것이 핵심 판매 포인트). |

### 3. [CTA 전환 모듈] Blueprint 솔루션 제시 (The Salvation Hook)
공포에서 해결책으로 넘어가는 가장 중요한 구간입니다.

| 요소 | 스펙/디자인 가이드라인 | 인터랙션 로직 (개발 지침) |
| :--- | :--- | :--- |
| **브릿지 카피** | 헤드라인: "이 결함은 자연적으로 사라지지 않습니다. [해결책]이 필요합니다." 폰트: 권위적이고 명확한 산세리프체. 배경: 약간 밝은 회색 계열의 '중립 지대' 느낌. | **[전환 효과]:** ASV 점수 섹션에서 이 모듈로 이동할 때, 화면 전체가 마치 *시스템이 재부팅되는 듯*한 짧고 날카로운 `화면 깜빡임(Flicker)` 애니메이션을 거쳐야 합니다. |
| **Blueprint 소개 박스** | 타이틀: "Marubyul Blueprint – 구조적 결함에 대한 설계도". 구성: 3단계 로직 플로우 다이어그램 + 다운로드 버튼. | **[핵심 CTA]:** 다운로드 버튼은 단순히 클릭되는 것이 아니라, 마치 '시스템 엔트리(System Entry)'를 활성화하는 것처럼 빛나고, 성공적으로 클릭되면 다음 단계로의 진입을 알리는 `SUCCESS_ACCESS` 애니메이션이 실행되어야 합니다. |
| **추가 문의 유도** | 톤: 위기감 유지. "전문적인 시스템 분석이 필요하신가요? (1:1 컨설팅)" 버튼 배치. | *미묘한 압박:* 이 섹션은 '선택'이 아닌 '필연적 요구'처럼 보이도록, 주변에 경고성 그래픽 요소(예: 빨간색 점멸하는 커서)를 배치해야 합니다. |
