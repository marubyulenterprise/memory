CI/CD 파이프라인 설정에서 'Secrets' 기능을 활성화하여 키를 안전하게 주입하는 최종 점검 항목.

### 🚨 경고: 지금 당장 해야 할 일 (Action Items)
현재 업로드 실패는 코드 자체의 문제가 아니라 **'민감 정보(API Key)'가 Git 히스토리 또는 배포 환경에 노출**되었기 때문일 가능성이 99%입니다. 이 체크리스트를 완수하면 보안 위험이 제거되고 정상적으로 재업로드가 가능합니다.

### 📁 Step 0: [필수] 과거 커밋 기록에서 키 완전 삭제 (Leakage Cleanup)
민감 정보가 이미 GitHub에 올라간 적이 있다면, 단순한 `.gitignore` 추가만으로는 부족하며 **히스토리 자체를 수정**해야 합니다. 이것은 가장 복잡하지만 가장 중요한 단계입니다.

1.  **필요 도구 설치:** `git filter-repo` (또는 BFG Repo Cleaner) 같은 전문 도구를 사용해야 합니다.
    *   *(명령어 예시: pip install git-filter-repo)*
2.  **키 제거 실행:** 리포지토리 전체의 모든 커밋 이력을 스캔하여, 지정된 패턴(API Key 형식 또는 실제 키 값)을 포함하는 파일을 영구적으로 삭제합니다.
    *   *(실행 전, 반드시 로컬 백업 브랜치를 생성하십시오.)*
3.  **강제 푸시 (Force Push):** 히스토리가 완전히 재작성되었으므로, 원격 저장소(Remote)에 강제로 덮어쓰기(Overwrite) 해야 합니다. 이 과정은 팀원들과 사전에 공지해야 합니다.

### ⚙️ Step 1: 로컬 환경 변수 설정 및 방어벽 구축 (Local Prevention)
개발자의 컴퓨터와 프로젝트가 외부 키에 의존하는 방식을 표준화합니다.

1.  **`.env` 파일 생성:** 프로젝트 루트 디렉토리에 `.env` 파일을 생성하고, 모든 API Key를 여기에 *변수로* 작성합니다. (절대 코드에 직접 입력 금지)
    ```dotenv
    # 예시: .env 파일 내용
    API_KEY=your_local_development_key_here
    DATABASE_URL="postgresql://user:pass@host:port/db"
    ```
2.  **`.gitignore` 수정:** 프로젝트의 방어벽 역할을 하는 `.gitignore` 파일을 열고, 다음 내용을 *반드시* 추가합니다.
    ```gitignore
    # .env 파일과 모든 환경 변수 관련 설정 파일을 Git 추적 대상에서 제외
    .env 
    /node_modules # (혹시 모를 노드 패키지 폴더)
    ```
3.  **코드 수정:** 프로젝트 코드 내부의 키 사용 부분을 `process.env.API_KEY` 형태로 **환경 변수 호출 방식**으로 전면 교체합니다.

### 🚀 Step 2: 배포 환경(CI/CD) 보안 점검 및 최종 테스트 (Deployment Guard)
개발자가 코드를 실제로 빌드하고 운영하는 자동화된 파이프라인을 점검합니다.

1.  **Secrets 기능 활성화:** 사용 중인 CI/CD 플랫폼 (GitHub Actions, GitLab CI 등)의 설정 페이지로 이동하여 **'Secrets' 또는 'Environment Variables' 섹션**에 접속합니다.
2.  **키 주입 확인:** 이 Secrets 영역을 통해 API 키를 안전하게 저장하고, 해당 변수가 빌드 단계에서만 접근 가능하도록 권한 설정을 완료했는지 점검합니다. (절대 코드 파일로 커밋되지 않도록 설정).
3.  **최종 테스트:** 모든 수정사항 적용 후, **가장 간단한 단위의 테스트(Unit Test)**를 실행하여 로직이 정상적으로 작동하는지 확인하고, 이를 통해 전체 시스템을 재배포합니다.
