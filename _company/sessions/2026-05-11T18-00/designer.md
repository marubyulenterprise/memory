## 🖥️ Critical Defect Report UI Mockup 및 디자인 브리프 (V1.0)
본 모형은 사용자가 '진단 요청' $\to$ '위기 인지' $\to$ '해결책 구매'의 흐름을 경험하는 데 초점을 맞춘 인터랙티브 웹페이지의 상세 기획안입니다. 단순한 이미지가 아닌, **상태 변화(State Transition)**에 따른 시각적/경험적 지침서로 기능합니다.

---

### 📐 1. 전체 디자인 시스템 & 테마 정의
*   **전체 배경:** Dark Mode (Deep Navy `#0A1423` 또는 Black)
*   **메인 컬러 (Normal):** Cyan Blue (`#00FFFF`) - 안정적인 데이터, 표준 정보 표시용.
*   **경고/위험 컬러 (Warning):** Amber Yellow (`#FFD700`) - 주의 신호, 미흡한 부분 강조.
*   **결함/최대 위험 컬러 (Crisis):** Critical Red (`#FF3B30`) - 시스템 오류, 즉각적 구매 유도 섹션 전용.
*   **폰트:** Monospace 계열 (예: Source Code Pro 또는 JetBrains Mono) — 기술적 권위와 해킹 느낌 부여.

### 🚦 2. 인터랙티브 시퀀스 설계 (State Flow Visual Logic)

| 단계 | API 호출 상태 | 핵심 경험 목표 | 시각적 구현 요소 |
| :--- | :--- | :--- | :--- |
| **Step 1: 진단 요청** | `POST /v1/diagnosis/run` (Input) | 사용자 입력 데이터 수집 및 초기 긴장감 조성. | 깨끗한 UI, Cyan Blue의 기본 그리드 패턴. '데이터 로딩 중...' 메시지와 함께 미세한 글리치(Glitch) 효과 삽입. |
| **Step 2: 결과 출력** | `POST /v1/diagnosis/run` (State Detected) | $L_{index}$ 점수와 현재 위험 레벨을 충격적으로 노출. | **상태별 시각 필터 적용.** (Normal $\to$ Warning $\to$ Crisis로 색상 변화가 전면 배경에 스며들도록 설계). |
| **Step 3: 결함 상세 보고** | N/A (Report View) | 공포를 측정 가능한 수치와 권위 있는 용어로 구조화. | 적색 경고 박스, 시스템 오류 로그(Log Dump), 데이터 플로우 다이어그램을 활용하여 시각적 복잡도를 높임. |
| **Step 4: CTA 전환** | `POST /v1/purchase/validate` (Pre-CTA) | 공포 절정 이후의 '유일한 탈출구'로서 해결책 제시. | 강렬한 대비(Red $\to$ Cyan Blue), 카운트다운, 버튼을 중심으로 모든 시각 요소가 수렴함. |

### 🚨 3. 섹션별 상세 Mockup 및 구현 지침 (Actionable Blueprint)

#### A. $L_{index}$ 점수 게이지 & 상태 경고 시스템 (The Fear Generator)
*   **위치:** 페이지 최상단, 사용자의 시선이 즉시 머무르는 곳.
*   **디자인:** 낡은 모니터의 디스플레이를 연상시키는 크랙(Crack) 효과와 네온 빛을 활용합니다.
*   **구현 지침:**
    1.  $L_{index}$ 점수를 중앙에 크게 표시하고, 그 주변으로 게이지 바가 가로질러 배치됩니다.
    2.  점수 변화 시 (Normal $\to$ Warning $\to$ Crisis), 게이지의 색상과 배경의 노이즈(Noise) 패턴이 **동기적**으로 변해야 합니다.
        *   *(Example: Warning 진입 시)* 화면 전체에 낮은 주파수의 '삐-'하는 시스템 경고음을 삽입하고, UI 요소 주변에 앰버색 플리커링(Flickering) 효과를 적용합니다.

#### B. Critical Defect Report (공포의 구체화)
*   **디자인:** 마치 해킹된 서버의 로그 파일이나 군사 기밀 문서를 열람하는 듯한 느낌을 주어야 합니다.
*   **요소 1: 결함 영역 시각화 (Misconception Alert 대체):**
    *   제목: `[SYSTEM ALERT] CRITICAL DEFECT DETECTED IN MODULE P2:`
    *   배경: Deep Navy 바탕에 Red/Cyan Blue의 교차 패턴 그리드를 배경으로 깔고, 해당 섹션만 **글리치(Glitch) 필터가 적용된 오버레이**를 씌웁니다.
    *   내용 구성: "당신이 인지하지 못한 [구체적인 결함]은 현재 시스템에 $\text{X}$ 시간의 손실을 초래할 잠재적 위험 요인입니다."와 같이, 구체적인 시간/금액 단위로 공포를 수치화합니다.
*   **요소 2: 원인 분석 데이터 플로우 (System Flow Diagram Placeholder 대체):**
    *   결함을 설명하는 다이어그램은 단순 연결선이 아닌, **'손실 경로(Loss Path)'**의 형태로 보여야 합니다. 화살표가 파란색 대신 빨간색으로 깜빡이며 '데이터 유출 위험', '비효율적 프로세스 경로' 등을 표시해야 합니다.

#### C. 최종 CTA 전환 영역 (The Conversion Point)
*   **배치:** 보고서 내용을 모두 읽고 공포가 절정(Crisis State)에 달했을 때, 페이지의 끝단에 강력하게 배치합니다.
*   **시각적 브리프:**
    1.  **비주얼 임팩트:** 갑작스럽게 모든 Red/Cyan Blue 효과가 멈추며, 화면 중앙에 **흰색의 깨끗하고 명료한 구조물(The Solution)**이 나타나야 합니다. 이 대비가 충격입니다.
    2.  **카운터 & 시간 제한:** 타이머를 삽입합니다 (예: `TIME LEFT TO MITIGATE DEFECTS: 00:15`). 이 카운터는 페이지 로드와 동시에 작동하며, 불안감을 극대화합니다.
    3.  **CTA 버튼 디자인:** 버튼은 단순한 사각형이 아닌, **'데이터 포트(Data Port)'**처럼 보이도록 디자인합니다. 주변에 전기적인 아크(Arc) 효과를 넣고, 마우스를 올리면 (Hover) 전압이 차오르는 듯한 애니메이션을 적용합니다.
    4.  **문구 구조:** 공포 유발 $\to$ 책임감 부여 $\to$ 해결책 제시 순서로 명확하게 분리합니다.
        *   (Headline): "🚨 경고: 이 결함은 시간이 지날수록 가속화됩니다."
        *   (Body): "즉각적인 개입이 필수적입니다. [Critical Defect Report]를 통해 손실 공포의 근원을 파악하고 시스템을 복구하세요."
