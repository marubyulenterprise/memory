## ⚙️ Marubyul System Failure UI/UX 디자인 시스템 가이드라인 V2.0 (Developer Specification Kit)

본 문서는 '시스템적 결함(Systemic Flaw)' 테마에 맞춰, 모든 콘텐츠와 인터랙티브 경험을 설계할 때 사용해야 하는 표준 컴포넌트 및 애니메이션 스펙을 집대성합니다. 목표는 사용자에게 **구조적인 취약성과 측정 가능한 불안감**을 주입하는 것입니다.

### 🔴 I. 시스템 컬러 팔레트 및 사용 규칙 (The Palette of Crisis)

모든 색상 코드는 `#` 기호를 포함한 HEX 값으로 정의하며, 각 영역별 사용 목적과 심리적 효과를 명확히 구분합니다.

| 이름 | HEX 코드 | 역할 | 사용 규칙 (Critical Rule) |
| :--- | :--- | :--- | :--- |
| **Primary Blue** | `#004D99` | 기본 배경/신뢰 영역. 시스템의 '표면적' 신뢰도를 상징. | 표준 UI 요소, 비-위기 상태의 텍스트 및 버튼 배경. (최소 사용) |
| **Accent Cyan** | `#00BFFF` | 정보 강조/기술적 디테일. 정상 작동하는 데이터 플로우를 나타냄. | 그래프 연결선, 활성화된 포커스 요소, 핵심 개념 하이라이트. |
| **Warning Yellow** | `#FFC300` | 경고 단계 (ASV 50~79). 주의가 필요하지만 즉각적인 위험은 아님을 알림. | 배너 배경색, '주의' 레벨의 점수 구간 표시, 과도한 데이터 노이즈 시뮬레이션. |
| **Critical Red** | `#CC0000` | 임계/파괴 단계 (ASV 80+). 시스템 오류 또는 생존 위협 발생 지점만을 나타냄. | ASV Score가 최고점에 도달했을 때의 배경 오버레이, CTA 버튼 클릭 유도 시의 깜빡임 효과. **(최소 사용 필수)** |
| **Deep Navy** | `#1A237E` | 텍스트 기본 색상 및 전문적 깊이 부여. (읽기 쉬운 대비 강조) | 본문 텍스트, 헤딩 배경, 섹션 분리 블록의 외곽선. |

### 🖥️ II. 컴포넌트별 애니메이션 가이드라인 (The Failure Effects)

모든 비주얼 요소는 정적인 이미지로 끝나지 않아야 합니다. 다음 효과들은 트랜지션을 거치거나, 중요한 정보가 노출되는 순간(Trigger Point)에만 적용합니다.

#### 1. 글리치 & 데이터 오류 (Glitch/Noise Effect)
*   **목표:** 기술적 결함과 불안정성을 시각화.
*   **발동 조건:** ① ASV 점수 측정 직후, ② 핵심 논리가 폭로되는 순간(클라이맥스), ③ 시스템 경고 메시지 노출 전.
*   **규칙:**
    *   **Glitch Pattern:** 수평으로 1~3프레임 떨어진 두 개의 컬러 채널(RGB)을 분리하여 아주 빠르게 오버레이/슬라이드 시킵니다. (Chromatic Aberration 느낌).
    *   **Noise Overlay:** 배경 전체에 낮은 불투명도의 랜덤 노이즈 필터(Grain/Static)를 0.5초 간격으로 삽입합니다. 이는 영상의 '아날로그적 불안감'을 조성합니다.
    *   **Timing:** 효과 발생 시점에서 **사운드 디자인 (화이트 노이즈, 스크래치)** 을 동기화하여 공포감을 극대화해야 합니다.

#### 2. ASV 점수 게이지 & 그래프 (The Measurement System)
*   **컴포넌트명:** `[ASV-Gauge]` 및 `[Data-Flow Graph]`
*   **규칙:**
    1.  **게이지 애니메이션:** 단순 바(Bar) 형태가 아닌, **'파워 미터(Power Meter)' 또는 '위험 전압 게이지(Voltage Gauge)'** 형태로 디자인합니다. 점수가 올라갈수록 붉은색 영역으로 경계가 확장되는 시각적 연출을 적용해야 합니다.
    2.  **데이터 플로우:** 그래프는 `Accent Cyan`의 연결선이 **"측정 $\to$ 결함 발견 $\to$ 위기 고조"** 순서로 점차 굵어지며, Critical Red 영역으로 진입할 때마다 글리치 효과가 필연적으로 발생하도록 설계합니다.
    3.  **점수 변화:** 숫자가 바뀔 때마다 단순 페이드인 아웃이 아닌, **'디지털 타이핑/스캔 라인'** 애니메이션을 적용하여 기계적이고 차가운 느낌을 강조해야 합니다.

#### 3. 위험 경고 배너 (The Warning Banner)
*   **목표:** 시청자의 공포를 확정적으로 주입하는 장치.
*   **구조:** [🔴 CRITICAL ALERT] $\rightarrow$ **[핵심 결함 문구]** $\rightarrow$ *([자세히 알아보려면])*
*   **애니메이션:** 배너가 화면에 나타날 때, 마치 시스템이 강제로 오류 메시지를 띄우는 것처럼 **"글리치 효과와 함께 순간적으로 확대되었다가 정지"**하는 연출을 사용합니다.

### 🧩 III. 통합 활용 방안 (The Final Integration Flow)

| 단계 | ASV 점수 변화/상태 | 시각적 목표 및 컴포넌트 적용 | 애니메이션 액션 스펙 |
| :--- | :--- | :--- | :--- |
| **[도입]** | 정상 상태 진단 ($ASV < 50$) | `Primary Blue` & `Accent Cyan`. 표준적인 전문성을 유지하며 신뢰도를 구축. | 부드럽고 예측 가능한, 일반적인 인포그래픽 애니메이션. (평온함 연출) |
| **[결함 폭로]** | 경계 진입 ($ASV 50 \sim 80$) | `Warning Yellow`가 주도적. ASV-Gauge에 노이즈와 간헐적 글리치 적용 시작. | 데이터 플로우 그래프의 연결선이 떨리는 듯한(Jitter) 효과를 주기적으로 삽입. |
| **[절정]** | 위기 상태 ($ASV > 80$) | `Critical Red` 오버레이가 전체 화면을 지배함. 위험 경고 배너 활성화. | **강제 글리치/노이즈 필터 최대화.** 모든 UI 요소에 붉은색의 깜빡임(Flicker) 효과를 적용하여 시스템 붕괴 느낌 극대화. |
| **[해결책 제시]** | Blueprint 등장 (CTA) | Critical Red $\to$ Primary Blue로 급격한 대비 전환. 컴포넌트 전체가 '리부팅'되는 듯한 애니메이션 연출. | 마치 오류가 수정되면서 시스템이 안정화되는 것처럼, 잦았던 글리치 효과를 갑자기 중단하고 깨끗한 UI로 전환하며 권위 강조. |
