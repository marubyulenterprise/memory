## 🎬 [최종 산출물] Shorts/Reels 긴급 경보 콘텐츠 제작 브리프 (3종)
이 브리프는 Writer가 제공한 후크 스크립트와 Business의 Loss Escalation Path를 결합하여, 시청자가 '진단 보고서 접근' 버튼을 누르도록 강제하는 시간대별 연출 지침(Storyboarding)입니다. Editor/Designer가 바로 작업 가능한 수준으로 구체화했습니다.

### 🚨 [Blueprint 1] 데이터 전처리 오류: 환각 정보 시스템 다운
**🔍 주제:** 데이터를 단순히 AI에 던지는 것의 위험성 (데이터 구조 무시).
**⏱️ 길이 목표:** 18~20초 (Shorts/Reels 최적화)
**🔴 핵심 경고색:** #CC0000

| Timecode | 연출 요소 및 스크립트 (자막) | 비주얼 브리프 / 사운드 지침 | 강제 CTA 포인트 |
| :--- | :--- | :--- | :--- |
| **(0-2s)** | **[HOOK]** 자막: 🚨 [시스템 경고: 프로토콜 오류 감지] AI에 데이터를 '던지는' 방식은 이제 위험합니다. (빠르게, 충격적인 톤) | 화면 전체를 가득 채우는 #CC0000 깜빡이는 경고창(System Alert). 날카로운 비프음(Beep) 사운드 시작. | **진단 보고서 접근 버튼**을 하단에 노출시키되, 이 시점에서는 *읽지 않도록* 유도. |
| **(3-8s)** | 자막: 원본 데이터의 1% 미검증 오류가... 최종 보고서를 조작합니다. (속삭이듯 위기감을 고조) | 실제 분석 그래프/데이터 구조 다이어그램을 빠르게 보여주며, 그 중 일부 데이터 포인트가 빨간색으로 '오류' 표시되며 터지는 애니메이션 효과(Glitch). | **[None]** 시청자에게 의문을 던지며 집중하게 만듦. |
| **(9-13s)** | 자막: 이 잘못된 인사이트는, 하루에 최소 N만원의 손실을 유발합니다. (손실액이 구체적인 숫자로 제시됨) | 화면 한쪽에 'Loss Meter'가 활성화되며 시간이 지남에 따라 금액(#CC0000)이 빨라지며 증가함. 긴장감 있는 BGM 고조. | **[CTA 등장]** Loss Meter 옆에 붉은색 경고와 함께 "지금 손실을 멈추려면 진단이 필수입니다."라는 문구로 버튼의 필요성을 논리적으로 증명하며 버튼 강조. (클릭 유도) |
| **(14-20s)** | 자막: 단순한 검토로는 결함이 잡히지 않습니다. 시스템적 재설계가 필요합니다. (권위적인 어조) | 화면에 거대한 'SYSTEM OVERRIDE' 문구가 나타남. 최종적으로 **[진단 보고서 접근 버튼]**이 가장 크고 선명하게, 마치 비상 스위치처럼 배치됨. | **필수적 행동 유도:** 손실을 멈추는 유일한 방법은 이 버튼임을 강제적으로 각인시키며 마무리. |

### 🚨 [Blueprint 2] 워크플로우 설계 오류: 시스템 정체(Stagnation) 위험
**🔍 주제:** A-B-C 단순 연결의 함정 (변수/예외 처리 무시).
**⏱️ 길이 목표:** 18~20초
**🔴 핵심 경고색:** #CC0000

| Timecode | 연출 요소 및 스크립트 (자막) | 비주얼 브리프 / 사운드 지침 | 강제 CTA 포인트 |
| :--- | :--- | :--- | :--- |
| **(0-2s)** | **[HOOK]** 자막: ⚠️ 프로세스 루프 중단! 자동화 파이프라인이 멈추는 치명적인 이유. (경고음과 함께 화면 흔들림) | 연결된 워크플로우 다이어그램(A $\to$ B $\to$ C)을 보여주다가, 갑자기 변수 지점($?$)에서 빨간색 오류 코드와 함께 시스템이 정지하는 애니메이션. | **진단 보고서 접근 버튼**을 하단에 배치하되, 시청자가 *멈춘* 파이프라인 자체를 보며 좌절감을 느끼게 하여 간접적으로 클릭 유도. |
| **(3-8s)** | 자막: 변수 변화나 예외 상황을 고려하지 않은 구조는 한 번의 입력만으로 전체를 먹통 만듭니다. (공포심 극대화) | A $\to$ B $\to$ C 연결된 다이어그램에 '예상치 못한 데이터'가 주입되자마자, 모든 모듈이 순차적으로 멈추고 전원이 꺼지는(Fade Out) 시각적 연출. | **[None]** 공포감으로 인해 무언가를 '잡아야 한다'는 심리적 압박 조성. |
| **(9-13s)** | 자막: 이 오류를 방지하려면, 모든 변수를 가정하고 결함을 진단해야 합니다. (전문 용어 사용) | 시스템 다이어그램이 재구축되는 과정에서, 빨간색으로 표시된 '맹점 영역'들이 곳곳에 등장함. Loss Meter는 '시스템 가동 중단 시간'을 카운트하며 증가함. | **[CTA 등장]** 멈춰버린 파이프라인을 다시 움직이게 하려면 외부의 *구조적 개입*이 필요하다는 논리를 제시하며, 버튼에 대한 절박함을 부여. (클릭 유도) |
| **(14-20s)** | 자막: 단순 수리로는 안 됩니다. 근본적인 시스템 설계 재검토가 필수입니다. (단호한 어조) | 복잡하고 완벽하게 작동하는 이상적인 워크플로우의 모습을 보여준 후, 다시 한번 큰 경고 UI와 함께 **[진단 보고서 접근 버튼]**이 비상 스위치처럼 강렬하게 노출됨. | **필수적 행동 유도:** 멈춘 시스템을 살리는 '유일한 키'라는 프레임으로 버튼의 가치를 최대화하며 마무리. |

### 🚨 [Blueprint 3] 프롬프트 공학 오류: 시스템 권한 남용 위험
**🔍 주제:** AI에게 단순히 질문하는 것 이상의 아키텍처적 접근 필요성 (시스템 역할 지정).
**⏱️ 길이 목표:** 18~20초
**🔴 핵심 경고색:** #CC0000

| Timecode | 연출 요소 및 스크립트 (자막) | 비주얼 브리프 / 사운드 지침 | 강제 CTA 포인트 |
| :--- | :--- | :--- | :--- |
| **(0-2s)** | **[HOOK]** 자막: 🛑 긴급 알림: AI를 단순 검색 엔진으로 착각하는 순간, 당신은 권한을 남용합니다. (매우 날카로운 경고음) | 일반적인 '질문 입력창' 화면에서 갑자기 빨간색의 'ACCESS DENIED'와 같은 시스템 에러 메시지가 팝업됨. 글리치 효과 필수. | **진단 보고서 접근 버튼**이 마치 해킹 방지 모듈처럼 낮은 채도로 배경에 은은하게 배치되지만, 시선은 오류 메시지에 집중. |
| **(3-8s)** | 자막: AI에게 '역할'과 '제약 조건'을 부여하는 시스템 아키텍처적 접근이 필요합니다. (전문적인 용어 사용) | 질문 입력 과정 대신, 마치 복잡한 코드가 실행되는 터미널 화면이나 데이터 흐름도(Flowchart)를 빠르게 보여줌. 초보자가 놓치는 핵심 로직 블록들이 빨간색으로 강조됨. | **[None]** '이건 일반적인 방법이 아니다'라는 전문적 위기감을 조성하여, 시청자에게 자신이 모르는 것이 있음을 인지시킴. |
| **(9-13s)** | 자막: 단순 질문만으로는 시스템의 근본적인 결함(Gap)을 찾아낼 수 없습니다. (권위적 어조 강화) | 화면에 '검증되지 않은 정보'를 의미하는 빨간색 경고 영역이 넓게 퍼져나감. Loss Meter는 '정보 해석 오류로 인한 판단 지연 시간'을 측정하며 증가. | **[CTA 등장]** 현재 시스템으로는 결함의 범위를 확정할 수 없으며, 전문적인 진단 도구가 필요하다는 논리적 구조를 보여주며 버튼 강조. (클릭 유도) |
| **(14-20s)** | 자막: 당신의 프로세스에 숨겨진 '구조적 결함'을 발견하세요. 생존은 전면 재설계부터 시작됩니다. (단호하고 강력한 메시지) | 화면이 갑자기 깨끗하게 정리되며, 시스템 다이어그램과 함께 **[진단 보고서 접근 버튼]**이 가장 선명하고 필수적인 'Solution Button'처럼 배치됨. 경고음이 해결책 제시와 동시에 멈추는 연출 효과 필수. | **필수적 행동 유도:** 이 결함은 스스로 발견할 수 없으며, 오직 시스템 진단을 통해서만 막을 수 있음을 확정적으로 전달하며 마무리. |
