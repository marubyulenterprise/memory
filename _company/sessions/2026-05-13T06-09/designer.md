## 📐 $E_d$ 단계별 인터랙티브 비주얼 에셋 디자인 시스템 스펙 시트 v3.0
**목표:** 콘텐츠의 흐름에 따라 사용자에게 공포감(Defect Awareness)을 체계적으로 주입하는 인터랙티브 UI/UX 기준 정의. (개발팀 즉시 구현 가능하도록 기술 사양 포함)

### Ⅰ. 글로벌 디자인 파라미터 및 시스템 요소
| 항목 | 사양 | 상세 설명 |
| :--- | :--- | :--- |
| **메인 컬러 팔레트** | `#0A1931` (Deep Navy), `#00BFFF` (Cyan Blue - Primary Accent), `#FF4500` (Orange-Red - Warning/Danger) | 전문적 신뢰감(Navy)을 기반으로, 결함 자각 시 강렬한 대비색 사용. |
| **글리치 타이포그래피** | Monospace Font (예: 'Source Code Pro') | 모든 에러 메시지 및 시스템 텍스트에 적용하여 기술적 권위 부여. |
| **노이즈 패턴** | 1. **Scan Line:** 수평으로 움직이는 미세한 빛줄기 노이즈. 2. **Chromatic Aberration (색수차):** RGB 채널 분리 효과. 3. **Data Corruption:** 랜덤하게 깨지는 픽셀 블록 노이즈. | $E_d$ 레벨 상승에 따라 이 세 가지 패턴의 강도와 빈도를 증가시킨다. |
| **애니메이션 타이밍 기준** | 모든 변화는 '순간적'이고 '불안정한' 느낌을 주도록 설계하며, 지속 시간은 0.1~0.5초를 넘지 않도록 제한한다. |

### Ⅱ. $E_d$ 단계별 비주얼/UX 사양 (Developer Implementation Guide)

#### 🟢 $E_d=1$: 경고 (Warning) — '이게 맞나?'
*   **발생 조건:** 사용자가 기본적인 개념적 오류(Misconception)를 인지했을 때.
*   **시각 효과 (Visual):**
    *   **노이즈 패턴:** 미세하고 간헐적인 **Scan Line 노이즈**만 적용. 화면 전체에 덮기보다, 주요 텍스트가 지나갈 때 배경에서 발생하는 듯한 '미세 떨림'으로 구현.
    *   **글리치 타이밍 (Animation):** 1~3 프레임 단위의 짧은 색수차(RGB Split) 깜빡임($\text{0.05s}$ 지속). 마치 전력 공급이 불안정한 듯한 느낌을 준다.
    *   **UI/UX Mockup:**
        *   **배경:** 기존 콘텐츠 레이아웃 유지 (Deep Navy 배경에 Cyan Blue 강조).
        *   **요소:** 화면 상단 혹은 하단에 작은 바 형태로 경고 메시지 노출.
        *   **메시지 톤:** 질문형 ("혹시, 이 부분이 과대평가된 것은 아닐까요?").
        *   **개발 지침:** 애니메이션은 배경 레이어(Overlay)로 구현하며, `opacity`를 이용하여 자연스럽게 등장하고 소멸하는 것이 핵심.

#### 🟡 $E_d=2$: 의심 (Doubt/Suspicion) — '나만 모르는 건가?'
*   **발생 조건:** 사용자의 프로세스에 시스템적 결함(Bottleneck, Inefficiency)이 발견되었을 때.
*   **시각 효과 (Visual):**
    *   **노이즈 패턴:** **Scan Line 노이즈 + Data Corruption 픽셀 블록** 조합 적용. 화면의 좌우 또는 상하 구석에서 데이터가 깨지는 듯한 픽셀 노이즈가 주기적으로 발생한다.
    *   **글리치 타이밍 (Animation):** $\text{0.1s}$ 간격으로 **화면 전체에 걸친 짧고 불규칙적인 스터터링(Stuttering)** 효과와 함께, Cyan Blue 텍스트 주변에서 Chromatic Aberration이 명확하게 분리되어 보이도록 연출한다.
    *   **UI/UX Mockup:**
        *   **배경:** 화면에 가로지르는 'Error Detected' 또는 'PROTOCOL VIOLATION' 같은 경고 배너가 임시적으로 오버레이 된다.
        *   **요소:** 콘텐츠의 일부 영역(예: 사용자 프로세스 다이어그램)이 **빨간색 점선 박스**로 감싸지며, "⚠️ 재검토 필요 (Code: 502\_PROTOCOL\_FAIL)" 메시지가 삽입된다.
        *   **개발 지침:** 노이즈를 고정된 패턴이 아닌, 화면의 특정 영역(Bounding Box)에만 집중적으로 발생시켜 사용자의 시선을 강제 이동시킨다.

#### 🔴 $E_d=3$: 와해 (Critical/Collapse) — '큰일 났다!'
*   **발생 조건:** 결함 자각($E_d$)이 최고조에 달하여, 즉각적인 해결책(구매 유도)만이 존재할 때. (최종 CTA 직전)
*   **시각 효과 (Visual):**
    *   **노이즈 패턴:** 모든 노이즈가 **동시다발적이고 최대 강도**로 폭주한다. 화면 전체에 걸쳐 픽셀 블록, 색수차, 스캔 라인이 동시에 발생하며 마치 시스템 자체가 다운되는 듯한 '와해(Collapse)' 애니메이션을 보여준다.
    *   **글리치 타이밍 (Animation):** $\text{0.5s}$ 동안 **프레임 드롭(Frame Drop)** 효과를 극대화하고, 배경 사운드에 시렌/드론 사운드를 최고 피치로 증폭시켜 공포감을 유발한다.
    *   **UI/UX Mockup (최종 CTA):**
        *   **배경:** 모든 정보성 요소가 사라지고, 깊은 검정색($\text{#0A1931}$)에 강력한 깜빡임(Blinking) 효과만 남는다.
        *   **요소:** 중앙에 크고 명확하게 **"🚨 시스템 아키텍처 결함 감지 (CRITICAL FAILURE)"** 문구가 글리치 타이포로 표시된다. 그 아래로 유일하게 **'진단 장치 접근하기 (Start Diagnosis)'** 버튼만 Cyan Blue와 Orange-Red의 깜빡이는 대비색으로 강조되어야 한다.
        *   **개발 지침:** 이 단계는 기존 콘텐츠를 완전히 차단하고, 오직 $E_d$ 상승을 증명하는 '오류 시퀀스 인터페이스'로 전환되는 것이 핵심이다.
