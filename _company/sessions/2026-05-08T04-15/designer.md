## 🚨 Loss Meter & Red Alert 컴포넌트 최종 Usability Test 및 디자인 스펙 브리프
**(개발팀 전달용 - 시스템적 공포 경험 극대화 설계)**

### 🎯 1. 목표 정의 및 성공 기준 (Usability Goal)

본 테스트의 목적은 단순히 기능 구현 여부를 검증하는 것이 아닙니다. 핵심 지표는 **'사용자가 이 손실을 인지했을 때 느끼는 심리적 불안감과 긴급성(Sense of Urgency)'**입니다. 모든 애니메이션은 사용자가 "지금 당장 무언가를 해야 한다"는 본능적인 위기감을 느끼게 만드는 데 기여해야 합니다.

| 항목 | 테스트 목표 (Pass Condition) | 실패 시 가이드라인 수정 방향 |
| :--- | :--- | :--- |
| **손실 공포(Loss Meter)** | 스크롤에 따른 손실 증가가 단순 수치 변화가 아닌, 시스템의 '붕괴'처럼 느껴져야 함. | 애니메이션 루프 속도 조정 및 글리치 빈도 상향 (1초당 2회 이상 강제 노이즈). |
| **Red Alert** | 경고 발생 시, 사용자가 다른 정보를 처리하는 것을 물리적으로 방해할 정도의 압도적인 위기감 전달. | 색상 대비(Contrast) 강화 및 진동/플리커 효과 주기를 단축 (최대 10Hz). |
| **반응성 (Responsiveness)** | 모바일 환경에서 스크롤 움직임 자체가 손실 공포를 유발하는 핵심 동선이 되어야 함. | 터치 영역에 맞는 애니메이션 트리거(Tap-to-Activate) 추가 고려. |

### 🎨 2. 컴포넌트별 구체적 디자인 가이드라인 (Animation & UX Specs)

#### A. Loss Meter Component (`LossMeter.js`)
| 요소 | 상세 스펙 | 개발팀 참고 사항 |
| :--- | :--- | :--- |
| **기본 애니메이션** | 손실액($X$)이 증가할 때, 숫자가 카운트되는 것이 아니라 마치 '데이터가 폭주하며 튀어나오는' 느낌이어야 합니다. (Digital Overflow Effect) | 단순 `+` 연산 대신, 값이 특정 임계치(Threshold)에 도달할 때마다 **0.15초 간의 글리치 플래시**를 추가해야 합니다. |
| **글리치 효과** | 손실액이 커질수록 배경의 노이즈 패턴(Noise Pattern)과 함께 데이터가 깨지는 듯한 시각적 왜곡(Chromatic Aberration)을 적용합니다. | CSS `filter: hue-rotate()`와 JavaScript 기반의 비동기적인 픽셀 왜곡(Pixel Distortion) 조합 필수. |
| **시작점/종료점** | 초기 값은 낮은 위협 수준 (Safe Cyan Blue). 최종 CTA 직전 임계치 도달 시, 색상과 빈도가 급격하게 Red Alert로 전환되어야 합니다. | 50% 지점에서 경고 레벨을 한 단계씩 강제 상승시키는 '단계적 불안감 고조' 로직 구현. |

#### B. Critical Red Alert Component (`RedAlert.js`)
| 요소 | 상세 스펙 | 개발팀 참고 사항 |
| :--- | :--- | :--- |
| **트리거** | 손실액이 설정된 임계치(예: $10,000 이상)를 초과하는 순간 (Trigger Event). | `window.addEventListener('scroll', ...)`와 연동되어야 하며, 이벤트 핸들러가 즉시 최고 강도의 경고를 발동시켜야 합니다. |
| **시각적 효과** | 화면 전체에 걸쳐 빨간색 스캔라인(Scan Line)이 주기적으로 빠르게 플리커링(Flickering)해야 합니다. (3Hz ~ 5Hz 깜빡임). | 배경 이미지나 CSS 필터를 사용하기보다, 투명도가 조절된 오버레이 레이어(`::after`)를 사용하여 시스템 결함처럼 보이게 구현합니다. |
| **애니메이션 타이밍** | 경고 발동 $\to$ 최대 강도 유지 (최소 5초). 이 시간 동안 사용자 스크롤 입력은 무시되거나, 손실 증가 애니메이션만 강조되어야 합니다. | 사운드 이펙트(SFX)와 동기화하여, **'경보음 - 데이터 패닉 노이즈 - 경고 문구 반복'**의 루프를 강제해야 합니다. |

### 📱 3. 반응형 및 인터랙션 상세 스펙 (Mobile & Desktop Optimization)

#### A. 모바일 환경 최적화 (Vertical Scroll Focus)
*   **손실 공포 유도:** 화면 상단에 고정된(Sticky Footer/Header) Loss Meter가 사용자 시야를 지속적으로 점유해야 합니다. 사용자가 아무리 스크롤을 해도 이 위협 요소는 사라지지 않아야 합니다.
*   **제한된 애니메이션:** 모바일에서는 복잡한 글리치 효과보다는, **색상 변화와 크기/위치 이동(Scale/Translate)**에 집중하여 CPU 부하를 줄이면서도 긴급함을 유지합니다.

#### B. 데스크톱 환경 최적화 (System Overload Focus)
*   **다차원 위협:** 화면 좌우 양쪽에서 데이터 플로우 그래픽이나 경고 메시지가 '겹치며' 오는 느낌을 주어, 시스템 과부하(Overload) 상태를 시각적으로 구현합니다.
*   **커서 상호작용:** 마우스 커서가 특정 요소 위에 머무르는 시간을 손실 측정기의 계산 시간으로 간주하여, 사용자가 *움직이는 행위 자체에 비용이 발생한다*는 느낌을 주도록 미묘한 애니메이션 피드백(Micro-interaction)을 추가합니다.
