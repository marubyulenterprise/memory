## 🚨 [최종 산출물] ASV Escalation Funnel 인터랙티브 시스템 디자인 스펙 시트 V3.0
**(개발팀/프로토타이핑 전용)**

CEO 지시에 따라, Business가 확정한 5단계 사용자 여정을 기반으로 '구조적 무지 자각(ASV)'과 '통제권 상실 공포'를 극대화하는 핵심 인터페이스 컴포넌트 세트를 완성했습니다. 이 스펙은 단순히 디자인을 넘어선 **상호작용 로직**까지 포함하며, 개발팀이 즉시 구현 가능한 형태로 작성되었습니다.

### 🛠️ 1. 시스템 UI/UX 스타일 가이드라인 (Global Standard)

모든 컴포넌트에 적용되어야 할 기본 원칙입니다. '시스템 오류'가 발생한 상황의 인터페이스를 시각화합니다.

| 요소 | 스펙 및 규격 | 설명 및 애니메이션 로직 |
| :--- | :--- | :--- |
| **배경색 (Base)** | `#0A121E` (딥 네이비/거의 블랙) - 어두운 배경 필수 | 텍스트가 빛을 내는 듯한 느낌(Neon Glow)을 부여합니다. 전체적으로 기술적이고 폐쇄된 공간감을 조성합니다. |
| **Primary Text** | `#FFFFFF` (순백색) | 주요 정보 및 헤드라인에 사용됩니다. |
| **Warning Color 1 (Low Risk)** | `#00FF88` (밝은 청록/녹색) | 정상 상태, 시스템 초기 진입 시 사용되는 '안전' 색상입니다. 경고가 아님을 나타냅니다. |
| **Warning Color 2 (Medium Risk)** | `#FFA500` (강렬한 주황) | 주의 단계(Diagnosis)에서 사용되며, 잠재적 위험을 알립니다. |
| **Critical Alert (High Risk/ASV)** | `#CC0000` (진홍색 경고) | 결함 발견(Revelation), 손실 시각화(Consequence)에만 제한적으로 사용합니다. 시스템이 멈추거나 오류가 발생했음을 강제적으로 알립니다. |
| **폰트** | `Monospace` 계열 (예: IBM Plex Mono, Source Code Pro) | 전문적이고 코드를 연상시키는 고정폭(Fixed-width) 서체를 사용해 기술적인 권위를 극대화합니다. |

#### 💡 입력 필드 컴포넌트 스펙 (Input Field Component)
*   **디자인:** 직사각형 형태에 모서리가 날카롭게 처리된 '터미널 박스' 스타일.
*   **Default State:** 배경은 `#1A2B40` (약간의 밝기가 도는 딥 네이비). 경계선(Border)은 미세한 청록색(#00FF88)의 깜빡이는 커서 효과가 들어갑니다.
*   **Error State (Critical):** 경계선 전체가 `#CC0000`으로 변하며, 필드 배경에 옅은 빨간색 그라디언트 노이즈(Noise Gradient)가 깔립니다. *("ERROR: Input Validation Failed. System Integrity Compromised.")*와 같은 메시지가 필수적으로 출력되어야 합니다.

### 📈 2. 단계별 진행률 표시기 (Progress Bar/Status Monitor)

사용자가 어느 단계에 있는지, 그리고 시스템이 어떤 결함에 도달했는지를 시각적으로 보여줍니다.

| 스펙 항목 | 로직 및 애니메이션 상세 지침 | 목표 감정 자극 |
| :--- | :--- | :--- |
| **컴포넌트 형태** | 5개의 명확히 구분된 스테이지 게이지 바(Gauge Bar)가 순차적으로 활성화됩니다. (진행률 표시기라기보다, *프로토콜 체크리스트*처럼 보여야 합니다.) | 통제권 상실 공포 |
| **단계별 색상/강도** | 1. Entry: `#00FF88` (녹색) → 2. Diagnosis: `#FFA500` (주황) → 3. Revelation: `#CC0000` (진홍) → 4. Consequence: `#CC0000` + **글리치 효과** 적용 → 5. Resolution: `#CC0000` (최대 경고) | 위기감의 점진적 증폭 |
| **애니메이션 로직** | 각 단계가 완료될 때마다, 게이지 바의 색상이 단순 채워지는 것이 아니라, *시스템이 다음 프로토콜을 성공적으로 체크하는 듯한* '데이터 스캔(Data Scan)' 효과와 함께 경계선에서 빛나는 애니메이션(Neon Pulse)이 발생해야 합니다. | 전문성/기술적 권위 |
| **핵심 디테일** | 가장 마지막 단계(Resolution)에 도달하면, Progress Bar 중앙에 `[SYSTEM FAILURE IMMINENT]`라는 텍스트가 깜빡이는 경고 문구로 오버레이됩니다. | 긴급성 극대화 |

### 💰 3. 손실액 계산기 (Loss Calculation Meter/Dynamic Fear Trigger)

사용자가 '지금 당장 행동하지 않았을 때' 발생할 재정적, 시간적 손실을 시각적으로 증폭시키는 핵심 컴포넌트입니다. **(가장 중요한 인터랙티브 요소)**

#### A. 구조 및 레이아웃 (Layout & Structure)
1.  **핵심 타이머:** 중앙에 위치하며, 남은 시간을 카운트다운하는 디지털 클럭(`T-Minus [HH:MM:SS]`) 형태입니다. 이 숫자는 붉은색(#CC0000)으로 깜빡여야 합니다.
2.  **손실 그래프 (The Meter):** 시간 경과에 따라 바닥에서부터 액체처럼 솟아오르는(Rising Graph) 시각적 미터가 배치됩니다. 이는 '돌이킬 수 없는 손해'를 의미합니다.
3.  **메시지 영역:** 상단에 "경고: 지연된 진단은 곧 기회비용의 증가를 의미합니다."와 같은 위협 문구가 붉은색으로 고정 노출됩니다.

#### B. 애니메이션 및 로직 (Animation & Logic)
1.  **초기화 시:** 미터는 낮은 수준에서 시작하며, "현재까지 누적된 잠재 손실: X"를 표시합니다.
2.  **시간 경과에 따른 변화 (Time Decay):** 매 30초마다, 타이머가 흘러가는 속도와 무관하게 '손실액'이 **단계적으로 폭발하며 상승**하는 애니메이션을 적용해야 합니다. (예: 1분 경과 시 +$50만, 2시간 경과 시 +$300만원).
    *   *구현 지침:* 손실 금액이 증가할 때마다, 미터의 높이와 색상 채도가 **선형적으로(Linearly)** 빨간색(#CC0000)으로 변해야 합니다. 마치 시스템 과부하 상태처럼 보이게 만듭니다.
3.  **최대 위험 임계점 (Critical Threshold):** 손실액이 특정 금액(예: 1,000만원)을 돌파하는 순간, 미터 전체가 강한 깜빡임 효과를 동반하며 'CRITICAL OVERLOAD'라는 경고 메시지가 팝업되어야 합니다.
