## Ⅰ. 시스템 전반의 디자인 원칙 및 톤앤매너 (System Protocol Guide)

| 항목 | 스펙 내용 | 적용 지침 (개발자 참고 사항) |
| :--- | :--- | :--- |
| **전체 폰트** | `Courier New`, `monospace` 계열 (CLI 느낌 필수). | 모든 로그 및 경고 메시지는 고정폭 글꼴을 사용해야 함. |
| **색상 팔레트** | **Primary:** `#1e1e2f` (시스템 기본 배경) / **Accent:** `#4a90e2` (안전 정보/기본 플로우) / **Alert:** `#CC0000` (위협/손실 임계점) | 색상 변경 시 `transition-duration: 0.5s ease-in-out;`을 기본값으로 적용하여 급격하지 않게 위협감을 고조시킬 것. |
| **UX 목표** | 사용자가 '정보를 습득'하는 경험이 아닌, '시스템 결함을 발견하고 수정해야 하는 과제'라는 인식을 심어주는 것. | 모든 팝업/경고창은 정보 제공 목적의 모달(Modal) 형태가 아닌, **진단 시스템의 일부로 강제 삽입**되어야 함. |
| **톤앤매너** | 객관적, 기술적, 위협적 (Objective, Technical, Threatening). 감성적인 언어는 절대 사용 금지. | '당신은 ~해야 한다' 대신, '시스템 프로토콜에 따르면 ~가 필요합니다.' 구조를 채택할 것. |

## Ⅱ. 인터랙티브 요소별 상세 스펙 (Interactive Component Specs)

### 1. 시스템 경고창 (System Alert Modal / Toast)

| 레벨 | 위협도 | 색상/시각 효과 | 필수 문구 구조 | 애니메이션 타이밍 및 사운드 |
| :--- | :--- | :--- | :--- | :--- |
| **INFO** | 낮음 (Blue) | 배경: `#1e1e2f` / 텍스트: `#4a90e2` | `[PROTOCOL]`: [정보 유형]: 내용. | **팝업:** 부드러운 페이드 인(Fade In, 300ms). 사운드: 미니멀한 '삐-' (Bleep) 소리. |
| **WARNING** | 중간 (Orange/Yellow) | 배경: `#4d3a00` / 강조선: `rgba(255, 165, 0, 0.8)` | `[ALERT]`: [위협 코드]: 경고 발생 지점 및 영향 범위 설명. | **팝업:** 짧은 진동 효과 (Shake Effect)와 함께 표시. 사운드: 간헐적 '삐빅- 삐직-' 노이즈. |
| **CRITICAL** | 높음 (Red) | 배경: `#330000` / 강조선/텍스트: `#CC0000` | `[!!! CRITICAL BREACH !!!]`: [위험 시스템]: 현재 손실액 수치 및 즉각적 대응 필요성. | **팝업:** 강한 '글리치(Glitch)' 효과와 함께 화면 오버레이. 사운드: 지속적인 사이렌 경고음 (Siren Tone) + 낮은 톤의 울림. |

### 2. 손실 측정기 (Loss Meter) - 동적 시각화 가이드

| 요소 | 스펙 내용 | 애니메이션 로직 및 타이밍 | 개발자 액션 포인트 |
| :--- | :--- | :--- | :--- |
| **손실 값 변화** | 시간 경과에 따른 손실액 증가. (예: 0 → 1,000 USD) | 손실률이 특정 임계치(Threshold)를 넘을 때마다 `#CC0000`의 강도가 점진적으로 증가해야 함. (Red-shift 효과) | **CSS:** `background-color`의 RGB 값이 시간에 따라 변화하도록 JS로 제어 (`setInterval`). |
| **임계점 도달** | 손실액이 '결정적 위기' 수준에 도달했을 때. | 1. **Glitch Trigger:** 화면 전체가 짧게 깜빡이는(Flickering) 글리치 효과 발동 (0.1초 동안). 2. **UI Freeze:** 모든 인터랙티브 요소의 애니메이션이 일시적으로 멈추고, 경고창만 전면에 고정됨. | **CSS/JS:** `animation: glitch-effect 0.1s linear infinite;`를 적용하고, JS로 해당 클래스를 강제 토글해야 함. |
| **손실 미터 UI** | 측정된 손실액 옆에 'Time Elapsed'와 'Remaining Time'을 표시하여 시간적 압박감을 극대화할 것. | 타이머가 0에 가까워질수록 배경 색상 변화 속도를 가속(Acceleration Curve)시킬 것. | **JS:** 시간을 카운트하는 로직 외에, 경과 시간에 따른 시각적 변색 강도(`opacity` 또는 `hue-rotation`)를 추가할 것. |

### 3. 시스템 로그 창 (System Log Console)

| 요소 | 스펙 내용 | 애니메이션/연출 지침 | 개발자 액션 포인트 |
| :--- | :--- | :--- | :--- |
| **폰트 및 스타일** | `monospace` 필수, 배경은 Deep Navy 계열 `#1a1a28`. 글자는 하이라이트를 주어 가독성을 높일 것. | 모든 로그는 마치 실시간으로 '타이핑되는' 것처럼 보이게 해야 함 (Typewriter Effect). | **JavaScript:** `setTimeout` 또는 `setInterval`을 사용하여 텍스트를 한 글자씩 순차적으로 출력하는 로직 구현. |
| **로그 종류** | 세 가지 타입의 태그가 필요함: `[PROTOCOL]`, `[ERROR]`, `[DATA_STREAM]` | 각 로그 유형에 따라 다른 색상과 아이콘을 부여하여 시각적 구분을 명확히 할 것. | **CSS:** 클래스별로 전용 폰트 크기, 색상 코드(`color`)를 정의하고 적용할 것. (예: `[ERROR]`는 `#ff6b6b`). |
| **최대 로그 수** | 스크롤을 무한정 늘리기보다, 최신 정보가 보이도록 상위 N개(N=30)만 제한적으로 보여주는 것이 전문적임. | 오래된 로그는 자동으로 페이드 아웃되거나 축소되어야 함. | **JavaScript:** 로그 배열 관리 및 `scrollTop` 이벤트 리스너를 활용하여 스크롤 이벤트를 제어할 것. |

## Ⅲ. 종합 애니메이션/UX 타이밍 표 (Actionable Timing Table)

| 액션 시나리오 | 예상 시간 (Time) | 주요 효과 (Effect) | CSS 속성 및 트랜지션 | 목적 (Goal) |
| :--- | :--- | :--- | :--- | :--- |
| **정보 표시** (Info Alert 팝업) | T + 0.3s | Fade In / 시스템 메시지 출력 | `opacity: 0` $\to$ `opacity: 1` (Duration: 300ms) | 위협감을 최소화하며 정보 전달. |
| **경고 발생** (Warning Alert 팝업) | T + 0.2s | Subtle Shake / 경고음 노이즈 시작 | `@keyframes shake { ... }` (Repeat Count: 1, Duration: 200ms) | 사용자의 주의를 끌고 시스템 오류의 가능성을 인지시킴. |
| **위기 임계점 도달** (Critical Breach) | T + 0s | Red-shift / Glitch Trigger | `background-color` 급격 변화 & CSS Filter (Hue/Contrast 조절). | 사용자가 상황의 심각성을 *직접* 경험하도록 강제. |
| **데이터 로딩 시작** | 지속적 | Typewriter Effect (로그 출력) | JS로 텍스트를 한 글자씩 지연하여 배치 (`setTimeout`). | 기다림의 시간을 '진단 과정'처럼 느끼게 하여 몰입도를 유지. |
