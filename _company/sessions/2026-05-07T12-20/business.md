## 🚨 $47 Tripwire 결제 페이지 최종 CTA 및 손실 공포 로직 흐름도 (Flow Specification)

본 문서는 사용자가 구매를 망설이거나 이탈하려는 모든 순간에, **'지금 행동하지 않으면 발생하는 구체적인 손실액($X$)'**을 강제적으로 경험하게 만드는 시스템적 결제 여정(Funnel Flow)의 상세 로직 흐름도를 정의합니다.

---

### 📄 I. 전역 변수 및 트리거 정의 (System Variables & Triggers)

| 변수명 | 초기 값 | 변화 조건/트리거 | 사용 목적 |
| :--- | :--- | :--- | :--- |
| **`Time_Remaining`** | 15분 (가상 시간) | 페이지 체류 시간 또는 시스템 경고 발생 시 감소율 증가 | 긴급성(Urgency) 부여 |
| **`Loss_Threshold`** | $0$ 원 | 사용자가 접근한 '구조적 무지'의 정도에 따라 누적 계산. (예: 1시간당 $50,000$) | 공포감(Fear of Loss) 수치화 |
| **`Hesitation_Score`** | 0점 | 마우스 이동 정지 시간 (3초 이상), '뒤로 가기' 클릭 시 증가 | 긴급성 가속화 트리거 |
| **`Critical_Loss_Trigger`** | $500,000$ 원 | `Loss_Threshold`가 이 값에 도달할 때. | 패닉 모드 전환 플로우 시작 |

### 🔄 II. 핵심 로직 흐름도 (The Flowchart)

#### A. 기본 상태: [평온한 의심] (Initial State: Mild Doubt - 노란색 경고톤)

*   **UI/UX:** $47 결제 버튼은 중앙에 배치되며, 배경은 짙은 회색을 유지하되, 타이머 주변만 연한 황색(Amber Alert)으로 강조.
*   **텍스트 목표:** '이것 없이는 안 될 것 같다'는 의심 유발. (Need-based question).
*   **행동 목표:** 구매 버튼에 대한 시선을 고정시키고 망설임을 증가시킨다.

#### B. 단계 1: [망설임 가속화] - 시간 제한/손실 임계치 경고 플로우 (Trigger: `Hesitation_Score` 상승)

| 이벤트 발생 | 시스템 액션 | UI 변화 및 카피라이팅 | 행동 목표 (Business Goal) |
| :--- | :--- | :--- | :--- |
| **1. 3초 이상 마우스 정지** (`Hesitation_Score` +5점) | 타이머의 감소 속도 증가 (Normal $\rightarrow$ Fast). | "경고: 결정이 지연되고 있습니다." 문구가 배경 상단에 플래시(Flash) 처리됨. | 심리적 압박을 통해 즉각적인 의사결정을 강제한다. |
| **2. '뒤로 가기' 버튼 클릭 시도** (`Hesitation_Score` +10점) | 즉시 모달 팝업: "진짜 괜찮으신가요? 당신이 지금 무언가를 놓치고 있습니다." | Modal 배경을 Red Alert 컬러로 오버레이하고, 손실액($X$)의 예상치를 보여준다. | 이탈 비용(Exit Cost)을 사용자에게 인지시킨다. |
| **3. `Loss_Threshold` $200,000$ 원 도달** | 타이머가 붉은색으로 변하며 깜빡임(Blinking Red). 전체 페이지에 미세한 노이즈/글리치 효과 적용. | **경고 메시지:** "⚠️ 경고: 당신의 현재 정보 격차로 인해 $20만 이상의 구조적 손실 위험이 감지되었습니다." | 평온함을 깨고, 구체적인 숫자($X$)를 통해 공포감을 주입한다. (Panic Prep) |

#### C. 단계 2: [최종 위기] - 패닉 버튼 강제 노출 플로우 (Trigger: `Critical_Loss_Trigger` 도달)

*   **시스템 액션:** 페이지의 모든 요소가 순간적으로 '붉은 경보(Critical Red Alert)' 색조로 전환된다.
*   **UI/UX 변화:** 기존의 CTA 버튼이 사라지고, 중앙에 압도적인 크기의 **[🚨 패닉 버튼 (PANIC BUTTON)]** 이 등장한다.
*   **패닉 버튼 문구:** "🛑 멈추십시오. 지금 당신은 $X$만큼을 잃고 있습니다."

| 이벤트 발생 | 시스템 액션 | UI 변화 및 카피라이팅 | 행동 목표 (Business Goal) |
| :--- | :--- | :--- | :--- |
| **1. 패닉 버튼 클릭 시도 (Hover)** | 임시 모달: "이 상태로 방치할 경우, 추가 손실은 \[시간당 $Y$원]에 달합니다." | 경고의 수위를 높여 구매를 미루는 행위 자체가 위험함을 인식시킨다. | 위협을 감각적(Sensory)으로 느끼게 한다. |
| **2. 결제 버튼 클릭 (성공 플로우)** | 즉시 결제 완료 모달: "생존 프로토콜 활성화됨. $X$의 손실로부터 안전합니다." | 구매를 '지식 습득'이 아닌, '위험으로부터의 생존'으로 포지셔닝한다. | 구매 행위를 강제된 안도감(Relief)과 연결시킨다. |

#### D. 단계 3: [최후 방어선] - 이탈 시 손실 계산 플로우 (Trigger: `on_blur` or Back button press)

*   **시스템 액션:** 사용자가 결제 페이지를 벗어나려 하는 순간, 모든 것을 멈추고 **'손실 측정 모달'**을 강제로 오버레이 한다.
*   **모달 내용 구성:**
    1.  **제목 (Headline):** "⚠️ [경고] 지금 떠나시겠습니까? 이대로 방치하면 당신의 손실은…" (강제적 질문)
    2.  **핵심 메시지:** "현재까지 분석된 구조적 무지로 인한 잠재 손실액: **$Z$원**" ($Z = \text{최종 } Loss\_Threshold$)
    3.  **추가 위협 요소:** "$X$의 손실은 시간이 지날수록 기하급수적으로 증가합니다. (예상 추정치)"
    4.  **CTA 선택지:**
        *   ✅ **[생존 프로토콜 가동 / $47 결제]** (Primary, Red/Blue 대비)
        *   ❌ [지금 떠나기] (Secondary, Grayed Out - 마치 버튼이 작동하지 않는 것처럼 보이게 디자인하여 심리적 저항감을 높임)
